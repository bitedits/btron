B-Audio: PCM Output Stack

The audio egress of the B-System: a five-call VirtIO-Sound-compatible driver surface, host-backed on QEMU/POSIX builds, with PWM hardware target on Pi-class ports and a bounded, telemetry-paced queue discipline.

Scope

B-Audio specifies the PCM output path from application or synthesizer to audible samples: the driver surface in src/drivers/virtio/virtio.c declared by include/device/virtio.h (device id VIRTIO_ID_SOUND 25), the weak-stub fallbacks that let every port link, the Control Panel semantics in src/settings/sound.c, and the shipping consumers: the Cassette Hi-Fi deck (src/apps/audio_player.c), the Orchestra pipeline sink (virtiosndsink, see B-Media), the lilcu64 synthesizer pump (B-Sound), the tronMSX PSG mixer (B-MSX), and terminal/event chimes (src/apps/kagee.c).

On non-UEFI targets the "device" is host-backed (SDL2 QueueAudio, wire format AUDIO_S16LSB, 1024-frame period), which keeps the BTRON build matrix honest: the same five calls run on QEMU, POSIX, and bare-metal alike. Audio is explicitly optional: driver init prints whether PCM output is active and the system boots normally without it.

Part 1 — Architecture & Conceptual Model

1.1 Signal & Control Path

 producer (synth / deck / pipeline sink)
   │  int16 interleaved PCM frames
   ▼
virtio_sound_write(samples, frames)          src/drivers/virtio/virtio.c
   │  bytes = frames × channels × 2   (bound-checked to UINT32_MAX)
   ▼
device queue  ── SDL_QueueAudio (QEMU/POSIX host-backed)
            └─ VirtIO-Sound / HDA or BCM2835 PWM (target hardware)
   ▲
   │  virtio_sound_get_queued_bytes()  — depth telemetry for pacing
   │
 Control Panel (settings/sound.c): master output, event chimes/bell,
 driver select, sample rate, low-latency buffer size

1.2 Device Lifecycle

  1. Probe — virtio_driver_init_all() attempts virtio_sound_open(44100, 2) at boot; failure prints PCM output unavailable (audio is optional) and the system continues.
  2. Reconfigure — a second open on a busy device closes the current one first: open is total and idempotent-by-replacement, never a leak.
  3. Stream — repeated write calls queue PCM; each accepted call returns the frame count written. Writes on a closed device are rejected, not buffered.
  4. Close — close clears the queue, releases the device, and drops the audio subsystem; safe to call when already closed.

The only HDA reference in code is the Control Panel driver label; there is no register-level HDA driver yet, and this book does not claim one.

1.4 Queue Depth & Pacing

The driver surface is fire-and-forget at the call boundary (writes never block), so pacing is the consumer's contract: poll virtio_sound_get_queued_bytes() and keep the queue near one period (2–4 periods is the comfortable band on the host backend). This is the audio-side twin of B-Core's counted-drop discipline: an unpaced writer does not corrupt the stream, it just grows the latency, and telemetry makes that visible. The Control Panel's real-time target is a 128-sample low-latency buffer (2.6 ms at 48 kHz); the DAW requirement in doc/md/DAW.md is a round-trip of ≤ 5–8 ms with 44.1/48/96 kHz at 16/24/32-bit, direct (bypass) VirtIO-Sound access.

The Control Panel (src/settings/sound.c) holds the system-side mirror: Master Audio Output (with dB headroom), System Event Chimes & Terminal Bell, driver radio (VirtIO-Sound/HDA vs BCM2835 PWM), sample-rate selection, and the low-latency buffer switch — the single place where audio policy is decided, then consumed through the five driver calls.

Part 3 — API Reference (the five driver calls)

3.1 virtio_sound_open

virtio_sound_openint

Opens (or reconfigures) the PCM output device. A busy device is closed first, so repeated opens never leak handles. The device starts unpaused on success.

int virtio_sound_open(uint32_t sample_rate, uint8_t channels);
NameTypeDirDescription
sample_rateuint32_t[in]Hz; must be non-zero (44100 default, 48000 panel target).
channelsuint8_t[in]1 or 2; more than 2 is invalid.
ReturnCondition
VIO_OKDevice live; obtained channel count latched internally.
VIO_ERR_INVALRate 0, channels 0 or > 2, backend init failure, or UEFI target (no backend yet).

3.2 virtio_sound_write

virtio_sound_writeint

Queues interleaved S16 PCM frames. Never blocks; never partially accepts: the whole request is queued or the call fails. Overflow of the 32-bit queue byte field is checked before submission.

int virtio_sound_write(const int16_t *samples, size_t frames);
NameTypeDirDescription
samplesconst int16_t*[in]frames × channels × 2 bytes of little-endian S16.
framessize_t[in]Per-channel frame count; non-zero.
ReturnCondition
(int)framesQueued successfully.
VIO_ERR_INVALDevice closed, null buffer, zero frames, or byte overflow.

Postconditions

Caller may immediately reuse its buffer (copy-in semantics); playback latency is bounded by queue depth observed via virtio_sound_get_queued_bytes.

3.3 virtio_sound_close

virtio_sound_closevoid

Clears queued audio, closes the device, and releases the audio subsystem. Idempotent: safe on an already-closed device.

void virtio_sound_close(void);

3.4 virtio_sound_is_ready

virtio_sound_is_readybool

Non-destructive probe: exactly whether a write would reach a live device. Consumers render UI ("speaker lit / muted") from this instead of speculating.

bool virtio_sound_is_ready(void);

3.5 virtio_sound_get_queued_bytes

virtio_sound_get_queued_bytesuint32_t

Current queue depth in bytes — the pacing telemetry that turns latency into a measured quantity. Returns 0 when the device is closed.

uint32_t virtio_sound_get_queued_bytes(void);
Derived quantityFormulaTarget
queued framesbytes / (channels × 2)2–4 periods (~2048 frames)
queued latencyframes / sample_rate≤ DAW bound 5–8 ms round-trip

Part 4 — Canonical Code Examples

4.1 A paced render loop (synth pump pattern)

if (virtio_sound_open(44100, 2) != VIO_OK) return;     /* audio optional   */

int16_t block[2048];                                    /* 512 stereo frames */
for (;;) {
    /* keep ~2 periods queued: render only when the device is starving */
    while (virtio_sound_get_queued_bytes() < 2 * 512 * 2 * sizeof(int16_t)) {
        lilcu64_synth_render_frames(block, 512);        /* fill interleaved */
        if (virtio_sound_write(block, 512) < 0) break;  /* device vanished  */
    }
    sleep_until_next_period();                          /* UI-plane budget  */
}
virtio_sound_close();

4.2 Pipeline sink (Orchestra)

/* the virtiosndsink element's chain() is exactly: */
int n = virtio_sound_write((const int16_t *)buf->data,
                           buf->size / (2 * channels));
return (n == VIO_ERR_INVAL) ? -1 : 0;   /* counted refusal, never blocking */

Verification Status (honest account)

B-Audio currently ships as C code without a companion Coq/OCaml model. There is no audio_* entry in verify/models/ and this book deliberately cites none. Related verified material nearby: the audio plane budgeting is covered by the SMP/AMP and InterCore proofs (media_smp, media_intercore), and the buffer/refcount and queue laws a PCM stack needs are already specified in the NuStream pool and leaky-queue layer (media_rtp). The planned AV-sync proof pair (media_avsync_*, see B-Video and doc/md/VIDEO.md) will bind the audio and video clocks; until then, treat audio correctness claims as tested-code evidence, not theorem evidence.
