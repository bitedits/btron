Apps: Application Architecture & Tier-1 Suite

Comprehensive C99 specification for building native B-System applications: parameterized geometry constructors, the Tier-1 standard application suite (gterm, T-Editor, TAD Browser), multi-form-factor scaling without #ifdef, and in-window menu bar control.

1. Application Architecture & Multi-Form-Factor Scaling

B-System applications follow a clean parameterized lifecycle that allows running completely identical C99 source code across desktop workstations and mobile handsets without conditional compilation (#ifdef): 

 ┌────────────────────────────────────────────────────────────────────────┐
 │                      Universal Application Model                       │
 │                                                                        │
 │   Desktop Profile (1024x768)        ◄── Same ──►  Mobile Profile (480x640)
 │   • opn_wnd(title, x, y, w, h, ...) C99 Code      • Borderless, Titleless
 │   • Client bounds: (x+4, y+26)                    • Client bounds: (0, 0) 
 └────────────────────────────────────────────────────────────────────────┘

2. The Tier-1 Standard Application Suite

Application Source Module Primary Capabilities & Specifications
gterm src/apps/gterm.c Full VT100 / ANSI terminal emulator, dynamic column/row calculations, scrollback buffers, in-window menu bar with Alt+T shortcuts.
T-Editor src/apps/t_editor.c Authentic BTRON text and TAD segment editor, multi-line paragraph wrapping, TIP pre-edit integration, and Alt+O Fusen manipulation.
TAD Browser src/apps/tad_browser.c Hyper-data document viewer with immutable multi-window state isolation, embedded Fusen links, and history back/forward traversal.
Chat src/apps/chat.c Peer-to-peer B-System instant messenger, XML protocol serialization, and contact presence management.

3. In-Window Menu Integration & Helpers

Tier-1 applications export standardized helper functions declared in include/btron/apps.h to enable programmatic and mobile softkey menu control:

Helper Function Target App Description
gterm_is_menu_open gterm Returns TRUE if the terminal menu bar currently has an active open dropdown.
gterm_open_menu gterm Programmatically opens dropdown menu at index menu_idx (e.g. 0 for File, 3 for Terminal).
gterm_close_menu gterm Closes any active dropdown menu in the terminal window.
t_editor_is_menu_open t_editor Returns TRUE if the editor menu bar currently has an active open dropdown.
t_editor_open_menu t_editor Programmatically opens editor dropdown at index menu_idx.
t_editor_close_menu t_editor Closes any active dropdown menu in the editor window.

4. Application Suite API Reference

open_gterm_window_rect WND*

Constructs and maps a gterm terminal emulator window with custom bounds and window attributes.

WND* open_gterm_window_rect(H x, H y, H w, H h, UW attr);
open_t_editor_window_rect WND*

Constructs a T-Editor window targeting the specified file path with custom geometry.

WND* open_t_editor_window_rect(const char *filepath, H x, H y, H w, H h, UW attr);
open_tad_browser_window WND*

Opens an isolated TAD Browser window displaying the specified binary TAD file.

WND* open_tad_browser_window(const char *tad_file);

5. Canonical Implementation Examples

The following example demonstrates launching a terminal emulator scaled to an arbitrary viewport without #ifdef: 

#include <btron/apps.h>

void launch_mobile_terminal(void) {
    /* Launch gterm in borderless mobile viewport (480x534) */
    WND *wnd = open_gterm_window_rect(0, 0, 480, 534, 0);
    if (!wnd) return;

    /* Cycle menu programmatically via softkey */
    if (!gterm_is_menu_open(wnd)) {
        gterm_open_menu(wnd, 0);
    }
}
