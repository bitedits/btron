Cores: Real-Time Kernel & Process Lifecycle

Comprehensive C99 specification for kernel initialization, task dispatching, inter-process synchronization, VirtIO hardware abstraction, and symmetric multiprocessing (SMP).

1. Architecture & Conceptual Model

The Cores subsystem represents the foundational execution substrate of B-System. It implements a cleanroom Sakamura T-Kernel 2.0 / μITRON real-time executive coupled with a modular hardware abstraction layer.

1.1 Hardware Target Abstraction

B-System cores run unmodified application logic across five distinct deployment environments via compile-time target specialization (BTRON_TARGET):

  • POSIX Hosted (Target 0): Development and emulation environment on macOS / Linux using SDL2 and native pthreads.
  • T-Kernel 2.0 Bare-Metal (Target 1): Direct execution on ARM Cortex-A7 (Raspberry Pi 2B) and VirtIO virtual machines.
  • NTT DoCoMo FOMA Mobile (Target 10): Embedded keitai profile targeting TI OMAP2430 / ARM1136 with a 480×640 viewport.
  • x86_64 UEFI SMP (Target 4): Modern PC architecture with 64-bit multi-core SMP scheduling and VESA graphics.
  • NEC PC-98 (Target 5): Retro-computing architecture support for vintage Japanese workstation platforms.

2. Data Structures & Types

Shell Output Function Callback (ShellOutputFn)

typedef void (*ShellOutputFn)(const char *line, COLOR col, void *user_data);
Parameter Type Description
line const char* Null-terminated ASCII/UTF-8 string buffer to render.
col COLOR 32-bit ARGB color value for terminal text rendering.
user_data void* Opaque user pointer passed to the callback context.

SMP Core Descriptor (CPU_CORE_INFO)

typedef struct {
    UW  core_id;           /* Hardware APIC / CPU identifier */
    UW  status;            /* 0=Offline, 1=Booting, 2=Active Run */
    UW  task_count;        /* Number of tasks assigned to this core */
    UW  ticks_total;       /* Execution accounting ticks */
} CPU_CORE_INFO;

3. System Call & API Reference

btron_core_init void

Initializes core kernel memory pools, interrupt controllers, and subsystem dispatch tables.

void btron_core_init(void);
Preconditions Hardware VRAM and early UART console must be mapped. Postconditions Transitions kernel from UNINITIALIZED to SYSTEM_RUN.
btron_core_banner void

Emits the canonical B-System version banner, copyright attribution, and CPU architectural profile to the system log.

void btron_core_banner(void);
btron_core_mem_log void

Dumps the physical and virtual memory allocation maps, free page frame counts, and static pool boundaries to debugging consoles.

void btron_core_mem_log(void);
btron_core_hfds_log void

Verifies and logs the integrity of the Hierarchical File & Data System (HFDS) backing storage mount points.

void btron_core_hfds_log(void);
btron_core_print_ver void

Formats the complete B-System kernel version, compiler build stamp, and runtime target profile into a terminal stream.

void btron_core_print_ver(ShellOutputFn out_fn, void *user_data, const char *arg);
Parameter Direction Type Description
out_fn [in] ShellOutputFn Callback invoked for each line of version output.
user_data [in] void* Caller context passed directly to out_fn.
arg [in] const char* Optional formatting flags (e.g. "-v" for verbose).

4. Canonical Implementation Examples

The following example demonstrates initializing the core kernel, querying target version information, and routing output through a custom shell callback: 

#include <btron/core.h>
#include <stdio.h>

/* Custom terminal line printer callback */
static void my_terminal_printer(const char *line, COLOR col, void *user_data) {
    (void)user_data;
    printf("[KERNEL 0x%08X] %s\n", col, line);
}

int main(void) {
    /* Step 1: Bootstrap B-System core subsystem */
    btron_core_init();

    /* Step 2: Output banner and memory statistics */
    btron_core_banner();
    btron_core_mem_log();

    /* Step 3: Print formatted version to shell */
    btron_core_print_ver(my_terminal_printer, NULL, "-v");

    return 0;
}
