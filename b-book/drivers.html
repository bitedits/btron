Drivers: Hardware Abstraction & Peripherals

Comprehensive C99 developer specification for the B-System hardware abstraction layer (HAL): memory-mapped I/O (MMIO), VirtIO paravirtualization (block, net, console), VESA Linear Framebuffer (LFB), and real-time clock services.

1. Hardware Abstraction Layer (HAL)

The Drivers subsystem abstracts low-level bus topologies, CPU interrupt controllers, and peripheral I/O ports behind deterministic, non-blocking C99 interfaces adhering to NASA JPL Rule 3: 

 ┌────────────────────────────────────────────────────────────────────────┐
 │                    B-System Standard Device Interface                  │
 │                                                                        │
 │   [ File / VObject Layer ]  ◄── ID / Device Calls ──►  [ Drivers HAL ] │
 │   • opn_dev / cls_dev                                  • VirtIO Block  │
 │   • rea_dev / wri_dev                                  • VESA Video    │
 │   • ctl_dev (IOCTL)                                    • UART Console  │
 └────────────────────────────────────────────────────────────────────────┘

2. VirtIO Paravirtualization Subsystem

To deliver hyper-performant I/O in QEMU and cloud virtualization environments, B-System implements direct cleanroom VirtIO MMIO drivers:

VirtIO Device Device ID MMIO Base Address Operational Function
VirtIO Block 2 (0x02) 0x0a000000 Persistent HFDS backing store; DMA sector read/write transactions.
VirtIO Net 1 (0x01) 0x0a000200 Ethernet frame RX/TX queues for TCP/IP and Chat protocols.
VirtIO Console 3 (0x03) 0x0a000400 Early system log streams, debugger TTY, and serial console output.

3. Data Structures & Descriptors

Device Management Descriptor (DEV_DESC)

Defined in include/btron/device.h:

typedef struct {
    ID    dev_id;       /* Unique 32-bit device identifier */
    UW    type;         /* Device class (BLOCK, CHAR, NET, DISPLAY) */
    char  name[32];     /* Hardware device label */
    UW    flags;        /* Status flags (READONLY, DMA_CAPABLE, READY) */
    UW    block_size;   /* Native transfer block granularity */
    UD    total_blocks; /* Total sector capacity */
} DEV_DESC;

4. Device Driver API Reference

opn_dev ID

Opens a registered hardware device driver by name, acquiring exclusive or shared access.

ID opn_dev(const char *dev_name, UW mode);
rea_dev ER

Performs a synchronous DMA block read from the target device into a kernel-mapped buffer.

ER rea_dev(ID dev_id, UD start_block, void *buf, UW num_blocks);
wri_dev ER

Writes blocks from memory to non-volatile device storage, flushing write-back caches.

ER wri_dev(ID dev_id, UD start_block, const void *buf, UW num_blocks);

5. Canonical Implementation Examples

The following example demonstrates opening a VirtIO block storage driver and reading master partition metadata: 

#include <btron/device.h>

ER read_partition_header(void *out_header) {
    /* 1. Open primary VirtIO storage block device */
    ID disk = opn_dev("vda", 0);
    if (disk < 0) return disk;

    /* 2. Read first 512-byte sector */
    ER er = rea_dev(disk, 0, out_header, 1);
    
    /* 3. Close device handle */
    cls_dev(disk);
    return er;
}
