B-Book / Font

Font: Multi-Script Typography & Font Engine

Comprehensive C99 specification for the B-System multilingual typography engine: 16-plane TRON Character Code rasterization, JIS X 0208 / JIS X 0213 dot-matrix bitmaps, Classical Tibetan subjoined stacks, and Font Manager caching.

1. 16-Plane TRON-Code Architecture

The Font subsystem realizes Dr. Ken Sakamura's vision of a universal multilingual typography engine capable of encoding all historical and living human scripts without code-page collisions. 

 ┌────────────────────────────────────────────────────────────────────────┐
 │                      TRON-Code 16-Plane Structure                      │
 │                                                                        │
 │  Plane 1: JIS X 0208 / JIS X 0213 (Kanji, Hiragana, Katakana, Latin)   │
 │  Plane 2: Morohashi Dai Kan-Wa Jiten (Classical Chinese Characters)    │
 │  Plane 3: Additional East Asian Character Sets (Hanja / Hanzi)         │
 │  Plane 9: Classical Tibetan Buddhist Canon (Jomolhari Unicode Stack)  │
 │  Plane 15: Private Use Area (PUA / Corporate & Historical Glyphs)       │
 └────────────────────────────────────────────────────────────────────────┘

Each TRON character code (TC) is a 16-bit word representing a character within the currently active plane. Transition between planes is accomplished via the standard TRON Language Specification Escape Sequence (TAD @ts_tfont segment).

2. Glyph Formats & Structures

Glyph Bitmap Metrics Structure (GLYPH_METRICS)

typedef struct {
    H  width;        /* Rasterized glyph bitmap width in pixels */
    H  height;       /* Rasterized glyph bitmap height in pixels */
    H  advance_x;    /* Horizontal advance pen displacement */
    H  bearing_x;    /* Left side bearing offset */
    H  bearing_y;    /* Vertical ascent bearing offset from baseline */
} GLYPH_METRICS;

3. Classical Tibetan Complex Script Rendering

B-System includes dedicated cleanroom support for Classical Tibetan typography (tibetan_fonts.c), implementing the Extended Wylie Transliteration Scheme (EWTS) and vertical consonant subjoining:

  • Head Consonant (Mgo-can): The root radical positioned at the top of the glyph stack.
  • Subjoined Consonant (Vogs-can): Dependent consonants attached directly beneath the root (e.g. kya, kra, rgya).
  • Vowel Signs (Dbyangs): Diacritics positioned either above (Gigu, Grengbu, Naro) or below (Shabkyu) the vertical stack.

4. Font API Function Reference

get_glyph_bitmap const UB*

Retrieves a 1-bit monochrome dot-matrix bitmap pointer and dimensions for the given 16-bit TRON code.

const UB* get_glyph_bitmap(TC code, H *out_w, H *out_h);
Parameter Type Description
code TC (uint16_t) 16-bit TRON character code.
out_w, out_h H* Pointers receiving glyph width and height in pixels.
drw_tc_char H

Renders a single TRON character glyph at coordinates $(x, y)$ on the target graphic device with subpixel anti-aliasing. Returns the horizontal advance width in pixels.

H drw_tc_char(GDEV *dev, H x, H y, TC code, COLOR fg, COLOR bg);
utf8_to_tron / tron_to_utf8 int

Converts between standard multi-byte UTF-8 character sequences and 16-bit TRON character codes.

int utf8_to_tron(const char *utf8, TC *out_tc);
int tron_to_utf8(TC code, char *out_utf8, int max_len);

5. Canonical Implementation Examples

The following example demonstrates decoding a UTF-8 string into TRON codes and rendering each glyph into an offscreen graphic device: 

#include <btron/troncode.h>
#include <btron/dp.h>

void draw_multilingual_banner(GDEV *dev, H x, H y, const char *utf8_text) {
    const char *p = utf8_text;
    H cur_x = x;

    while (*p != '\0') {
        TC code = 0;
        int bytes = utf8_to_tron(p, &code);
        if (bytes <= 0) break;

        /* Render glyph with black foreground and transparent background */
        H advance = drw_tc_char(dev, cur_x, y, code, COLOR_BLACK, 0x00000000);
        cur_x += advance;
        p += bytes;
    }
}
