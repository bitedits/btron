B-Book / OpenGL

OpenGL: 3D Graphics Subsystem, Architecture & Backends

Formal C99 developer manual and architectural specification for the B-System OpenGL ES 1.1 3D graphics pipeline. Documents the uniform function pointer dispatch engine, EGL-lite window surface compositor bridge, and the six production and roadmap backends: TinyGL, VirtIO-GPU, Intel Gen12 i915 (Venus), Nintendo 64 (LibDragon), Sony PlayStation 2 (ps2gl), and Broadcom VideoCore IV.

Architectural Scope & Zero Post-Boot Allocations
The B-System 3D graphics subsystem provides an industry-standard, fixed-function OpenGL ES 1.1 API decoupled from physical hardware through a lightweight 26-method dispatch table. All display list allocations, vertex pipeline buffers, and depth buffers adhere to NASA JPL Rule 3 (zero dynamic heap allocation during live animation frames).

1. 3D Graphics Architecture & Pipeline Overview

In classic TRON specifications, 2D display primitives (GDEV) handled all desktop drawing. B-System extends this model by embedding a full 3D rasterization engine that treats window client canvases as offscreen color buffers. Applications call standard OpenGL functions (glMatrixMode, glRotatef, glLightfv, glCallList), which route transparently through the active backend into the window's backing pixmap:

2. Dispatch Table Architecture (gl_ops_t)

The core dispatch interface is defined in src/gl/gl_dispatch.h. It defines function pointers for all supported OpenGL ES 1.1 primitives, state toggles, and buffer presentation:

Category Dispatch Operations Description
Primitives gl_begin, gl_end, gl_vertex3f, gl_normal3f, gl_color3f, gl_color3fv Immediate mode vertex submission for GL_TRIANGLES, GL_QUADS, and GL_QUAD_STRIP.
Transformations gl_matrix_mode, gl_load_identity, gl_push_matrix, gl_pop_matrix, gl_translate_f, gl_rotate_f, gl_frustum, gl_viewport 4x4 matrix stack arithmetic for ModelView and Projection matrices (16 levels deep).
Buffers & State gl_clear, gl_clear_color, gl_enable, gl_disable, gl_shade_model Depth buffer clear (1.0e10f), color buffer clear, lighting toggles, culling, and smooth shading.
Lighting & Material gl_light_fv, gl_material_fv Ambient, diffuse, and specular illumination from directional and positional lights; front/back material responses.
Display Lists gl_gen_lists, gl_new_list, gl_end_list, gl_call_list Pre-compiled geometry lists enabling static mesh caching without per-frame vertex generation overhead.
Presentation swap_buffers Flushes rendered frame to underlying host/hypervisor driver (VirtIO scanout sync or VESA LFB).

3. EGL-lite Window Surface Bridge

Instead of requiring full EGL/X11 infrastructure, B-System introduces EGL-lite (src/gl/egl_surface.c). It seamlessly links any BTRON window (WND) with the active 3D rasterizer: 

/* Create EGL surface directly bound to window client device context */
EGL_SURFACE* egl_create_window_surface(WND *wnd) {
    if (!wnd || !wnd->dev || !wnd->dev->pixels) return NULL;
    EGL_SURFACE *surf = (EGL_SURFACE *)calloc(1, sizeof(EGL_SURFACE));
    surf->wnd    = wnd;
    surf->width  = wnd->dev->width;
    surf->height = wnd->dev->height;
    surf->pixels = wnd->dev->pixels;
#if defined(BTRON_UEFI_TARGET)
    gl_init(GL_BACKEND_TINYGL, surf->width, surf->height, surf->pixels);
#else
    gl_init(GL_BACKEND_VIRGL, surf->width, surf->height, surf->pixels);
#endif
    return surf;
}

/* Present frame: triggers backend flush and marks window region for WM compositor */
void egl_swap_buffers(EGL_SURFACE *surf) {
    if (!surf) return;
    if (g_gl && g_gl->swap_buffers) g_gl->swap_buffers();
    if (surf->wnd) inval_wnd(surf->wnd);
}

4. Production Backend 1: TinyGL Software Rasterizer

Production Status: Active in Bare-Metal x86_64 UEFI SMP
Source: src/gl/backend_tinygl.c | Credits: Fabrice Bellard & C-Chads

TinyGL is a high-performance, freestanding C99 software 3D rasterizer designed for operating environments with no libc, no FPU runtime helpers, and no GPU hardware. In B-System, it serves as the primary 3D engine for bare-metal UEFI:

  • Direct Framebuffer Rendering: Renders 32-bit ARGB8888 color directly into allocated window pixmaps without intermediate host driver translation.
  • Fixed-Point Depth Buffering: Operates a 16-bit or 32-bit Z-buffer with sub-pixel barycentric interpolation.
  • Zero Dependencies: Compiles cleanly under freestanding LLVM/Clang (-target i686-none-elf -ffreestanding -nostdlib).

5. Production Backend 2: VirtIO-GPU 3D (virgl) Cleanroom Acceleration

Production Status: Active in POSIX, QEMU, and Sakamura T-Kernel
Source: src/gl/backend_virgl.c | Credits: Gerd Hoffmann & Synrc Research Center

For virtualized environments running under QEMU or POSIX host emulation, B-System provides a cleanroom implementation of the VirtIO-GPU 3D (virgl) pipeline:

  • Complete gl_ops_t Dispatch: Implements all 26 vector table methods including matrix stacks, lighting, materials, and display lists.
  • View-Space Normal Lighting: Transforms normals by the upper 3x3 modelview matrix and computes Lambertian diffuse lighting ($N \cdot L$) against directional sources.
  • Screen-Space Winding & Culling: Correctly identifies counter-clockwise (CCW) front-facing triangles in top-left origin coordinates (area < 0), eliminating back-facing polygons without culling front-facing facets.
  • Palette Unification: Packs true 32-bit ARGB8888 words (0xFFRRGGBB), matching SDL2 SDL_BLENDMODE_NONE streaming textures and eliminating white fog or translucency leaks.

6. Future Roadmap: The Four Hardware 3D Backends

To expand B-System into bare-metal workstations and vintage consoles, four additional specialized hardware 3D backends are scheduled in the architecture roadmap:

3. Awe Morris Intel i915 (Venus Engine)

Target: Bare-Metal Intel Gen12+ Iris Xe / UHD Graphics (Tiger Lake, Alder Lake, Raptor Lake)
Design Specification: doc/txt/VENUS.txt

The Venus driver provides bare-metal hardware acceleration on modern Intel PC platforms:

  • Atomic Display Plane Page-Flipping: Replaces 3 MB software memcpy frame blitting with atomic PLANE_SURF register updates synchronized to hardware VBLANK, slashing CPU presentation latency from 3.2 ms to 12 microseconds.
  • Gen12 Render & Copy Engines (RCS0 / BCS0): Executes hardware BitBlt fragment kernels for rectangular window scrolling, drag previews, and solid fills.
  • Lock-Free Multi-Core Actor Model: UI plane on Core 0 produces requests into a single-producer queue; GPU request worker thread pinned to Core 1 handles CSB status buffers and ring submissions.

4. OpenGL for LibDragon (Nintendo 64)

Target: NEC VR4300 RISC CPU with Reality Coprocessor (RCP)
Architecture: Reality Signal Processor (RSP) Microcode & Reality Display Processor (RDP)

Adapted from the LibDragon homebrew ecosystem, this backend brings OpenGL ES 1.1 to the Nintendo 64 architecture:

  • RSP Vector Geometry Engine: Offloads vertex transformation, 4x4 matrix multiplication, clipping, and lighting calculations to the vector SIMD RSP unit running specialized geometry microcode.
  • RDP Hardware Rasterization: Commands stream directly via DMA to the RDP 1-cycle pipeline for hardware depth testing (16-bit Z-buffer in RDRAM), Gouraud shading, and perspective-correct texture mapping.
  • Zero-Copy Desktop Scanout: Video Interface (VI) scanout displays RDRAM framebuffers natively without CPU intervention.

5. OpenGL for PlayStation 2 (ps2dev / ps2gl)

Target: Sony PlayStation 2 (Emotion Engine R5900 + Graphic Synthesizer)
Architecture: Vector Unit 1 (VU1) Parallel Pipeline & 4 MB eDRAM GS Blitter

Leveraging the battle-tested ps2gl architecture pioneered by the ps2dev community:

  • VU1 Geometry Co-Processor: Vector Unit 1 executes microprograms in parallel with the 294 MHz R5900 core, transforming vertices and computing lighting at 66 million polygons/sec peak throughput.
  • VIF1 Direct DMA Packaging: Geometry batches are packed into VIF packets and transferred via high-speed DMA directly to the Graphic Synthesizer.
  • GS 4 MB Ultra-Wide eDRAM: Massive 48 GB/s internal memory bandwidth enables free 32-bit Z-buffering and alpha blending with zero bus stalls.

6. Broadcom VideoCore IV (Raspberry Pi)

Target: Raspberry Pi 2, 3, and Pi 400 (BCM2836 / BCM2837 / BCM2711)
Architecture: VideoCore IV 3D (V3D) Tile-Based Deferred Rasterizer (TBDR)

Direct hardware OpenGL ES 1.1 / 2.0 driver interfacing with the Broadcom VideoCore IV 3D hardware core:

  • Tile-Based Deferred Rendering (TBDR): Divides the 1024x768 screen into 64x64 pixel tiles. Primitives are binned into tile memory before rasterization, drastically reducing memory bandwidth on LPDDR2/LPDDR4 memory.
  • Direct MMIO V3D Control: Communicates with V3D register apertures (0x3F000000 / 0xFE000000), programming binning memory and render control blocks without Linux kernel or proprietary firmware blobs.
  • Hardware Cursor Overlay: Maps the BTRON mouse pointer directly to the HVS (Hardware Video Scaler) overlay plane for zero-overhead cursor motion.
