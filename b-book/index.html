B-Book: Developer's Systems & API Reference

The official technical specification, C99 API manual, and architectural guide for B-System — inspired by the classic BeOS/Haiku BeBook.

Architectural Scope
B-Book documents the core foundational libraries and system calls of B-System (BTRON 3.20 specification). All APIs follow strict C99 conformance, zero post-boot heap allocations (NASA JPL Rule 3), and clean multi-target abstractions across POSIX, Sakamura T-Kernel 2.0, NTT DoCoMo FOMA mobile, x86_64 UEFI SMP, and NEC PC-98.

1. The Five Core Subsystems

The B-System developer platform is partitioned into five distinct, decoupled subsystems. Each subsystem exposes public C99 headers in include/btron/ and is documented in its dedicated chapter:

2. TRON Standard Fundamental Data Types

B-System adopts the canonical TRON architecture fundamental type definitions declared in include/btron/types.h. All kernel interfaces and system calls rely on these fixed-width primitives:

TRON Type Underlying C99 Type Width Semantic Description
B int8_t 8 bits Signed 8-bit byte integer.
H int16_t 16 bits Signed 16-bit halfword integer; fundamental coordinate scalar.
W int32_t 32 bits Signed 32-bit word integer.
D int64_t 64 bits Signed 64-bit doubleword integer; 64-bit timestamps.
UB uint8_t 8 bits Unsigned 8-bit byte; byte stream payloads.
UH uint16_t 16 bits Unsigned 16-bit halfword; character indices and flags.
UW uint32_t 32 bits Unsigned 32-bit word; bitmask attributes and memory sizes.
UD uint64_t 64 bits Unsigned 64-bit doubleword; 64-bit hardware registers.
VW void* 32/64 bits Variable word; generic opaque pointer or user context.
ID int32_t 32 bits Kernel object identifier (Task, Window, Real Object, Semaphore).
ER int32_t 32 bits TRON system call error return code (ER_OK = 0; negative indicates error).
COLOR uint32_t 32 bits 32-bit RGBA pixel color (0xAARRGGBB format).
TC uint16_t 16 bits 16-bit TRON character code (16 planes supporting multilingual scripts).

3. Geometric Primitives

2D layout and clipping across all subsystems utilize two fundamental structures:

Point Primitive (PNT)

typedef struct {
    H x;  /* Horizontal coordinate in pixels */
    H y;  /* Vertical coordinate in pixels */
} PNT;

Rectangle Primitive (RECT)

typedef struct {
    H left;    /* Left boundary coordinate (inclusive) */
    H top;     /* Top boundary coordinate (inclusive) */
    H right;   /* Right boundary coordinate (exclusive) */
    H bottom;  /* Bottom boundary coordinate (exclusive) */
} RECT;
NASA JPL Rule 3 Safety Invariants
To ensure mission-critical stability and bounded real-time predictability:
  • Zero Post-Boot Dynamic Allocations: Applications and window structures must allocate buffers statically or during boot initialization. No dynamic malloc() during active rendering loops.
  • Strict Pointer Validation: All API functions validate input pointers and return ER_PAR on NULL inputs.
  • Bounded Loops: All search and traversal routines are bounded by compile-time capacity constants (e.g. APP_MENU_MAX_HEADERS, TIP_MAX_CLAUSES).
