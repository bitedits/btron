B-Book / VObject

VObject: Real Objects & Virtual Body Fusen

Formal C99 specification for the BTRON 3.20 hyper-data storage model: Real Objects (実身 / ROBJ), Virtual Objects (仮身 / VOBJ_LINK / Fusen), the TRON Application Databus (TAD) binary architecture, and non-hierarchical network graphs.

1. The BTRON Hyper-Data Model

Unlike traditional Unix or Windows file systems structured around rigid directory tree hierarchies, B-System implements the Real Object / Virtual Object (実身・仮身) hyper-data model designed by Dr. Ken Sakamura: 

 [ Real Object: Document A ] (実身)
            │
            ├── [ Virtual Object Link: Chart 1 ] (仮身 Fusen) ──► [ Real Object: Chart 1 ]
            │                                                             ▲
            └── [ Virtual Object Link: Memo 2 ] (仮身 Fusen)              │
                                                                          │ Shared Link
 [ Real Object: Cabinet B ]                                               │
            │                                                             │
            └── [ Virtual Object Link: Chart 1 ] (仮身 Fusen) ────────────┘
  • Real Object (実身 / ROBJ): The actual persistent data payload stored on disk (text, vector graphics, audio, or application code). Each Real Object has a unique 32-bit identifier (robj_id).
  • Virtual Object (仮身 / VOBJ_LINK): A lightweight interactive pointer (also known as a Fusen) embedded inside documents or cabinets. A single Real Object can be referenced simultaneously by multiple Virtual Objects without duplication.
  • Zero File Paths in User Space: Users navigate the hypermedia network solely by clicking Virtual Body Fusen links, eliminating folder browsing, path strings, and file open/save modal dialogs.

2. Data Structures & Types

Virtual Object Type Enumeration (VOBJ_TYPE)

Defined in include/btron/vobj.h:

typedef enum {
    VOBJ_TYPE_TEXT     = 1,  /* Pure text document or TAD rich text stream */
    VOBJ_TYPE_DRAW     = 2,  /* 2D vector drawing and graphic canvas */
    VOBJ_TYPE_EXEC     = 3,  /* Executable application binary or script */
    VOBJ_TYPE_FOLDER   = 4,  /* Cabinet / container holding multiple Fusen links */
    VOBJ_TYPE_TERMINAL = 5   /* Interactive shell terminal / communication session */
} VOBJ_TYPE;

Real Object Descriptor (ROBJ)

typedef struct {
    ID        robj_id;      /* Unique 32-bit Real Object Identifier */
    VOBJ_TYPE type;         /* Data format payload category */
    char      name[64];     /* Human-readable object label */
    char      path[256];    /* Backing store physical file system path */
    UW        size;         /* Content payload size in bytes */
} ROBJ;
Field Type Description
robj_id ID (int32_t) Globally unique non-zero object ID.
type VOBJ_TYPE Payload type determining default editor and viewer handler.
name char[64] UTF-8 display name shown on Fusen links.
path char[256] Physical path in backing storage directory.
size UW (uint32_t) Current size of Real Object payload in bytes.

Virtual Object Link (VOBJ_LINK)

typedef struct {
    ID        vobj_id;      /* Virtual Body link instance ID */
    ID        target_robj;  /* Target Real Object ID referenced by this Fusen */
    char      label[64];    /* Custom link label (defaults to ROBJ name) */
    PNT       pos;          /* Embedded (X, Y) pixel position inside host document */
} VOBJ_LINK;

3. TRON Application Databus (TAD) Architecture

Real Object contents are encoded using the binary TRON Application Databus (TAD) format. A TAD file consists of a stream of 16-bit tagged segments:

Segment Tag Hex ID Payload Structure Description
@ts_tpage 0xFFA0 Page geometry, margins, dimensions Document layout bounding box.
@ts_truler 0xFFA1 Indents, line pitch, tab stops Typographic paragraph layout rules.
@ts_tfont 0xFFA2 Font ID, TRON plane, typeface Font binding for subsequent characters.
@ts_tchar 0xFFA3 Point size, font weight, color Character level formatting overrides.
@ts_vobj 0xFFA8 target_robj, label, icon type Embedded Virtual Body Fusen hyperlink.

4. VObject API Function Reference

init_vobj_sys ER

Initializes the Real/Virtual Object hyper-data subsystem and binds the storage root directory.

ER init_vobj_sys(const char *storage_root);
cre_robj ROBJ*

Creates a new persistent Real Object with the given name and data type, returning its descriptor.

ROBJ* cre_robj(const char *name, VOBJ_TYPE type);
opn_robj ROBJ*

Opens an existing Real Object by its 32-bit identifier.

ROBJ* opn_robj(ID robj_id);
cls_robj ER

Closes an active Real Object, synchronizing modified buffers to disk.

ER cls_robj(ROBJ *robj);
cre_vobj_link VOBJ_LINK*

Instantiates a Virtual Body (Fusen) link pointing to the specified target Real Object at coordinates $(x, y)$.

VOBJ_LINK* cre_vobj_link(ID target_robj_id, const char *label, H x, H y);
rd_vobj_data / wr_vobj_data ER

Reads or writes raw binary TAD payload bytes from/to an open Real Object.

ER rd_vobj_data(ROBJ *robj, void *buf, UW len, UW *read_bytes);
ER wr_vobj_data(ROBJ *robj, const void *buf, UW len);

5. Canonical Implementation Examples

The following example demonstrates creating a Real Object and embedding a Virtual Object Fusen link: 

#include <btron/vobj.h>

void create_document_with_fusen(void) {
    /* 1. Create target Real Object (e.g. quarterly report) */
    ROBJ *report = cre_robj("2026年度 業績報告", VOBJ_TYPE_TEXT);
    if (!report) return;

    /* 2. Write initial TAD content */
    const char msg[] = "B-System 3.20 Executive Briefing";
    wr_vobj_data(report, msg, sizeof(msg));

    /* 3. Create a Virtual Body Fusen link to embed into a Home Cabinet */
    VOBJ_LINK *link = cre_vobj_link(report->robj_id, "業績報告書", 32, 64);
    (void)link;

    /* 4. Flush and close */
    cls_robj(report);
}
