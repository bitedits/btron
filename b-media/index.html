B-Media: Abstract Pipes, Budgets & the SMP Substrate

The media scheduling layer of the B-System: a GStreamer-shaped pipe graph with per-plane CPU budgets, running on the verified CAS multicursor ring and the AMP I/O-core protocol.

Scope & Layering

B-Media specifies the abstract media pipes: a pipeline/graph subsystem in the shape of GStreamer, built into the kernel tree with zero external dependencies (src/apps/orchestra.c), and the real-time substrate those pipes are budgeted on — plane periods and WCET budgets (include/btron/async_rt.h), the CAS multicursor ring with per-producer lanes (src/cores/core_smp.c), the AMP I/O-core heartbeat/takeover handshake, and the wait-free seqlock pointer snapshot.

Part 1 — Architecture & Conceptual Model

1.1 The Abstract Pipe Graph

A pipeline is a linear array of up to 16 elements; each element exposes exactly one source pad and one sink pad; linking peers the two pads and chains buffers src→sink. Pads carry fixed 512-byte buffers with PTS/DTS timestamps; an in-band bus records the last message and a count. Elements are minted by a factory from a small static type set — there is no runtime plugin loader, matching the zero-post-boot-allocation rule inherited from B-Core. 

[midisrc] ─► [midiroute] ─► [fluidsynth] ─► [audioconvert] ─► [virtiosndsink]
   src→sink pad chain; GstBuffer{data,pts,dts}; bus message per state change

1.2 Pipeline State Machine

Every element and the pipeline itself move through the same five states:

VOID_PENDING → NULL → READY → PAUSED ⇄ PLAYING
  • NULL — resources released; the only state safe to free/abandon a pipeline from.
  • READY — resources acquired, no data flow.
  • PAUSED — sinks primed, one buffer may drain (the preroll position).
  • PLAYING — chain functions run and timestamps advance from the pipeline base time.

Transitions return SUCCESS, ASYNC (preroll pending), or FAILURE; a failure leaves the prior state intact — the same "refusal is inert" discipline as the InterCore calls.

1.3 Plane Periods & Budgets

Each pipe runs inside an actor pinned to a plane with a fixed period and a WCET budget (async_rt.h): the input plane every 1000 µs with a 500 µs budget, the UI/presentation plane every 8333 µs with 4000 µs, the I/O defer actor on the AMP core free-running at 250 µs with 500 µs, and the media decoder on a spare core. All four actor priorities are equal (100): ordering comes from budgets and cursor backpressure, not from a priority ladder.

1.4 The CAS Multicursor Ring

The Tier-2 message path is a byte ring of capacity ring_cap with one lane per producer. A producer claims a byte range with a single CAS on the packed cursor word (the multicursor commit of platform.rs lineage), fills it, then publishes. Readers may consume only published bytes, which is exactly the tearing hazard the packed word closes. Claims that would exceed capacity or the unpublished window (inflight_max) are refused — never blocked, never wrapped. The invariants are byte-level conservation: accepted + dropped is what producers asked for, delivered + in-commit-window is what is readable, and an over-capacity read is BAD_CURSOR, refused and counted.

1.5 AMP I/O-Core Handshake & Takeover

Before the I/O core (core 3) runs the drain loop alone, boot hands it over with a release/ack handshake; afterwards the core beats a heartbeat every period. Two bars govern ownership (hardening plan §6.5, rev-2 ruling): at 50 ms of missed beats the UI logs a warning; at 100 ms the UI takes over draining. At most one drain owner exists at any time, and a stolen drain is visible in telemetry rather than silently duplicated.

1.6 Wait-Free Pointer Path (Seqlock)

The pointer plane never takes a lock: producers accumulate into a seqlock word (seq, acc_dx, acc_dy, acc_wheel, buttons); readers snapshot before/after and accept the sample only when the sequence number is unchanged and even. A torn read is retried, so the UI plane can never observe a half-applied motion batch — and the accumulated deltas are monotone between accepted snapshots. This is the batching that satisfies the ≤2 ms pointer-gap row of the pass table.

3.6 Ring & seqlock operations (substrate contract)

claim / publish / rcv / stealring

The producer path is two-step — claim reserves bytes on the lane with one CAS, publish makes them readable. rcv consumes only published bytes; steal is the takeover drain. Names below are the oracle surface that the src/mp C header must preserve.

GstPipeline sym;

gst_element_factory_make(&sym, "midisrc",      "keys")  -> sink_pad;

4.2 Budgeted drain with takeover

/* UI plane: bounded catch-up per period; IOD actor on AMP core 3. */
for (;;) {
    period_wait(UI_PERIOD_US);                       /* 8333 µs           */
    unsigned k = 0;
    rcv r;
    while (k < UI_TRB_BUDGET && (r = rcv(lane_i, want)).kind != EMPTY) {
        consume(r.bytes);                             /* DATA only         */
        if (r.kind == BAD_CURSOR) telemetry_refused++;
        k++;
    }
    /* heartbeat: stall 50 ms = warn, 100 ms = UI drains via steal() */
    if (io_heartbeat_age_ms() > IO_WARN_MS)  log_warn();
    if (io_heartbeat_age_ms() > IO_TIMEOUT_MS) steal(io_lane, backlog);
}

Verification Cross-Reference

The substrate layer is proved in verify/models/media_smp_properties.v (69 closed judgements) against the oracle media_smp_model.ml; the theorem dossier lives at b-media/theorems/media_smp.html. Headline results:

  • rcv_is_never_blocking — the ring rcv is total over its three contract states; no implicit yield exists.
  • mp_zero_refines_legacy — with BTRON_MP=0 the gated build steps identically to the legacy path (the gate is additive, never a rewrite).
  • mp_gate_is_additive, gate_does_not_change_observed_delta, gate_off_cannot_observe_ring — disabling the gate is unobservable, so a shipped one-core port cannot be fooled into claiming ring behaviour.
  • Byte conservation of the ring (inflight = readable + in-commit), no-tearing reads, single AMP drain owner with the 50/100 ms bars, and monotone seqlock accumulators.

The cursor layer above is verified in B-Core (602 judgements). The global scheduling layer (media_model.ml, the pass table itself) currently ships as the oracle only: its header names media_properties.v as companion proof, and that file does not exist yet — an honest gap, tracked here rather than papered over. Do not cite global-layer results as Coq-proven until that file lands.
