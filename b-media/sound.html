B-Sound: Lil Cu 64 Procedural Synthesizer

The sound processor of the B-System ceremony: an assetless, deterministic DSP engine — 48-voice legacy pool plus a 4096-node scheduled WebAudio-equivalent graph — that renders 44.1 kHz stereo S16 PCM directly onto the B-Audio driver surface, with every mascot gesture phase-locked to a procedural sound shim.

Scope & the 0-Byte Doctrine

B-Sound specifies the synthesis side of audio: src/demo/lilcu64_synth.c/.h (lifecycle, voice pool, shims, VirtIO pump), src/demo/lilcu64_wa.c/.h (scheduled node engine), src/demo/lilcu64_score.c (1:1 transcriptions of the four index.html track scores), and src/demo/lilcu64_demo.c/.h (the demoscene window that consumes them). Normative prose: doc/txt/SOUND.txt (shim physics, DSP primitives, timing equations) and doc/txt/LILCU64-DEMOSCENE.txt (kinematics ↔ shim wiring, track cue tables).

Zero-byte footprint. No sample files (WAV, AIFF, OGG) exist in this repository. Every sound — bell, Rhodes, frog croak, industrial bass — is computed at runtime by analytical DSP at 44,100 Hz. Consequences: zero load latency, sub-100 KB code budget, pitch/filter morphing without sample-artifacting, and perfect frame-accuracy against the 60 FPS render tick.

B-Sound never touches hardware: it renders into an int16_t buffer and hands it to the five B-Audio driver calls (virtio_sound_write and friends), whose weak stubs — declared right here in lilcu64_synth.c — keep every port of the build matrix linkable with no audio device at all.

Part 1 — Architecture & Conceptual Model

1.1 The Audio-Visual Shim Principle

From SOUND.txt §0: every fundamental 3D kinematic action of the character maps 1-to-1 to a deterministic procedural DSP algorithm called a Sound Shim. A shim S(t₀, p) takes a trigger time and a parameter vector (pitch, volume, decay) and builds y(t) = Σₖ Aₖ(t−t₀) · Wₖ(2πfₖ(t−t₀) + φₖ) * Hₖ(t) — waveforms × exponential ADSR envelopes convolved through biquad bodies — then self-disposes when its envelope reaches zero. Shims are stateless at call time; state lives only in the voice pool.

1.2 Dual Synthesis Topology

The engine mixes two independent synthesis domains into one stream every 32-frame block (RENDER_BLOCK): 

 UI thread                    audio-render tick (32 frames ≈ 0.73 ms)
   │                            ┌───────────────────────────────────────────┐
 play_track(n) ──gen bump──▶    │ timeline_tick()   loop/apply score change │
                               │ wa_render(mix)    WA graph → float mono,  │
                               │                   advances audio clock    │
                               │ update_sequencer  (legacy, idle)          │
                               │ for each SynthVoice: wave, 1-pole LP,     │
                               │   AM trem, freq glide, const-power pan    │
                               │ legacy×(30000/32767) + wa_mix             │
                               │ master_soft_clamp → int16 interleaved     │
                               └───────────────────────────────────────────┘
   legacy domain: 48 SynthVoice slots (one-shot shims, drums, chimes)
   WA domain:     up to 4096 scheduled WaNodes (the 4 full track scores)

The two domains keep different headroom conventions, made explicit in render_block(): legacy voices are scaled as if they were already int16 (× 30000.0f/32767.0f), while the WebAudio graph targets the ±1.0 range that ctx.destination clamps in the JS original. The shared master_soft_clamp (§2.4) reconciles them before int16 conversion.

1.3 Clock & Thread Model

The single source of truth is the audio clock — wa_time(), seconds of rendered samples, the exact analogue of AudioContext.currentTime. The UI/scheduler clock is never consulted for musical time. This is the demoscene twin of B-Core's ruling R7: producers never block on consumers, and consumers read a monotonically advanced clock they alone drive.

  • UI → audio handoff is a single volatile int s_track_gen counter bumped with __sync_fetch_and_add; the audio thread notices the delta inside timeline_tick() and applies it. No mutex, no queue, no lost update.
  • The pump guards re-entrancy with __sync_lock_test_and_set(&s_pumping, 1) — a second concurrent pump_virtio returns 0 immediately instead of double-writing PCM.
  • Track time for choreography is wa_time() − s_tl_base wrapped into the loop length, so mascot cues are sample-accurate (~0.7 ms granularity), not timer-accurate.
  • Looping re-schedules with s_tl_base += len (not = wa_time()), so drift cannot accumulate across hours of playback — the same absolute-scheduling discipline as ctx.currentTime + offset in JS.

1.4 Track Lifecycle

  1. Play — lilcu64_synth_play_track(n): deactivate all 48 legacy voices, reset sequencer state, bump the generation counter. Returns immediately.
  2. Apply — within one render block, timeline_tick() sees gen != applied_gen: wa_stop_all() (the C twin of stopAllTracks), looks up lc_score_length(n), latches the timeline track, sets s_tl_base = wa_time(), and schedules the whole score ahead on the audio clock.
  3. Loop — when wa_time() ≥ s_tl_base + len: stop all, advance the base by exactly one loop length, reschedule. (JS reference: playTrack(n, true) at 25 800 / 28 000 / 26 800 / 25 800 ms.)
  4. Stop / toggle — the same track number again, or an out-of-range number, stops: generation bump, voices cleared, timeline track 0. Mute additionally zeroes the WA mix and kills legacy voices, while the clock keeps advancing.

2.2 Legacy Voice (lilcu64_synth.c)

typedef struct {
    bool   active;
    int    wave_type;      /* 0 SINE, 1 TRIANGLE, 2 SAW, 3 PULSE, 4 NOISE, 5 FM_BELL */
    float  phase;          /* radians, wrapped at 2π                                  */
    float  phase_inc;      /* 2π·freq/sample_rate, re-derived on glide                */
    float  freq, target_freq, freq_ramp_rate;  /* exponential pitch glide            */
    float  amp;            /* linear decay envelope: amp -= decay_rate each sample    */
    float  decay_rate;     /* 1/(decay_time·sample_rate); voice dies at amp ≤ 1e-4    */
    float  pan;            /* −1.0 … +1.0, constant-power cosine/sine law             */
    float  fm_ratio, fm_index, fm_phase;       /* 2-op FM (shimPulseBell: 2.76 × 1.8) */
    float  filter_lp, filter_coeff;            /* 1-pole lowpass body/formant         */
    float  am_freq, am_phase, am_depth;        /* AM tremolo (frog croak 32 Hz)       */
} SynthVoice;               /* 48 slots, static array — no heap, no post-boot alloc */

Invariants: every field is written by the audio thread only between render blocks; allocation is first-fit then lowest-amplitude steal, so a trigger never fails and never blocks — the audible worst case is a quiet voice cut short. This is refusal-as-stuttering again, in the audio plane (see B-Core §1.4).

The engine header states the contract: "Every node is scheduled ahead on an absolute audio clock (seconds), … so the scores play 1:1 and are locked to the VirtIO sound sample clock, not to the UI/scheduler."

2.4 Master Soft Clamp (verbatim)

static inline float master_soft_clamp(float x) {
    if (x > 1.25f)  return 1.0f;
    if (x < -1.25f) return -1.0f;
    if (x > 0.85f) { float d = x - 0.85f;  return 0.85f + d / (1.0f + d * 2.5f); }
    if (x < -0.85f){ float d = -x - 0.85f; return -(0.85f + d / (1.0f + d * 2.5f)); }
    return x;
}

Linear below ±0.85, saturating rational knee to ±1.0, hard cut above ±1.25: the WaveShaper warmth of SOUND.txt §5.2 distilled to three branches, guaranteeing int16 convertibility of every frame.

3.3 lilcu64_synth_get_active_track / get_track_time

track read-backint / float

The choreography interface. get_track_time() returns seconds elapsed inside the current loop iteration: (wa_time() − s_tl_base) mod loop_length, for timeline tracks only; legacy tracks return the sequencer cursor.

int lilcu64_synth_get_active_track(void); /* 0..4 */ float lilcu64_synth_get_track_time(void); /* seconds within loop */

Preconditions / invariants

Safe from any thread (reads plain state; worst case a one-block-stale value). Value never exceeds the loop length and never goes backwards within an iteration — cues may be evaluated once per 16 ms frame with no monotonically-violating surprise.

3.4 lilcu64_synth_render_frames & lilcu64_synth_pump_virtio

render / pumpvoid / int

render_frames fills interleaved stereo S16 exactly — host backends, WAV-less capture, tests. pump_virtio is the realtime pacing loop against the B-Audio queue telemetry.

void lilcu64_synth_render_frames(int16_t *out_pcm, size_t frames); int lilcu64_synth_pump_virtio(size_t frames);
ReturnCondition (pump_virtio)
0Another thread is pumping (re-entrancy gate); queue already at target; or the refill was written.
−1Device not ready even after one opportunistic open(44100,2).

Pump algorithm

target = 17640 B ≈ 100 ms of S16 stereo
missing_frames = (target − virtio_sound_get_queued_bytes()) / 4
                clamped to [requested frames, 5292 frames = 120 ms]
loop: render ≤1024 frames → virtio_sound_write(chunk) until shortfall closed

No blocking, no unbounded buffering: playback stays locked to real time and worst-case added latency is one 100 ms target window — the audio twin of B-Media's plane budgets (B-Media).

Verification Status (honest account)

B-Sound currently ships as C code without a companion Coq/OCaml model. There is no sound_* or lilcu64_* entry under verify/models/ and this book cites none. The engine's structural disciplines are individually verified in other books' models — bounded pools (B-RTP's NuStream object model, 24-slot buffer pool media_rtp), never-blocking counted refusals (media_intercore I-series), plane budget execution (media_smp) — and the 1:1 JS↔C score transcription is held by the cue tables of LILCU64-DEMOSCENE.txt §5.3/§8, verified per-track against index.html millisecond values. What is not yet proven: sample-level determinism of the shim DSP, pool-steal continuity, and the audio↔video clock binding — the last is the planned media_avsync pair shared with B-Video and B-Audio. Until a model lands, treat every B-Sound correctness claim as tested-code evidence, not theorem evidence.
