B-RTP: WebRTC Core, MCU/SFU

The multipoint real-time media plane: SRTP ingest per peer, a 16-slot grid compositor, deterministic temporal queues, and the NuStream zero-allocation pipeline model that lands this discipline on the verified B-Core transport.

Scope & the Determinism Continuum

B-RTP specifies three layers of one continuum, unified in doc/md/GST-SYNC-RTP.md: the production WebRTC MCU compositor (ingest → mix → broadcast + record), the deterministic synchronization discipline (thread-isolated leaky queues, absolute temporal drop, timestamp monotonicity), and NuStream, the same pipeline philosophy stripped to a hard real-time, zero-allocation C99 object model for RTOS deployment — the intended resident media shape on the B-System µITRON / AMP / InterCore substrate.

In-tree realization: src/nus/nus_gst.c — the self-contained signaling peer process (Erlang rtp_broker-supervised, newline-delimited JSON over stdio) driving webrtcbin per participant; and the oracle/proof pair verify/models/media_rtp_model.ml ↔ media_rtp_properties.v which specifies the media-plane laws (pools, leaky queues, dilation, budgets, lifecycle, grid geometry, tier gating, RTP sequence arithmetic) independent of any host library.

MCU vs SFU: the shipped topology is an MCU — mixing is server-side (video grid + additive audio mix) and every participant receives one composite. The SFU posture (forwarding per-peer streams without decode) is a downstream-branch choice: the tee points after parse and before pay preserve PTS/DTS per stream, so per-peer passthrough branches can be added without touching the ingest path.

1.1 MCU Pipeline Topology

Peer ⇄ webrtcbin (SRTP/SRTCP, 50 ms budget)

   ┌────┴──── Ingest (per peer) ────────┐

   └───────────────────────────────────┘        │
                            vtee / atee ◄── tees after h264parse, before rtp pay
                              │
             ┌────────────────┼────────────────┐
             ▼                ▼                ▼
        per-peer rtp sink   HLS / fMP4      crash-resilient disk branch

Three simultaneous roles: upstream ingest (independent webrtcbin + decodebin chains per peer), mixing/compositing (spatial grid 1920×1080, additive audio), and downstream broadcast + recording (re-encode to every participant while writing HLS or fragmented MP4).

1.2 Peer Join & Ordered Teardown

Join (setup_peer) — six ordered steps:

  1. Allocate the first free grid slot (0…15).
  2. Create webrtcbin with the 50 ms latency budget.
  3. Create leaky broadcast queues (leaky=2, max-size-time=1 s).
  4. Link vtee → v_queue → webrtcbin.sink_0 and the audio counterpart.
  5. gst_element_sync_state_with_parent.
  6. Asynchronous SDP offer generation.

Departure (cleanup_peer) — six-stage reverse-conserving release: unlink queues → release compositor/audiomixer pads → remove decode chains → free webrtcbin → free grid slot. The oracle checks that join and leave are exact resource inverses (join_resources vs leave_releases): a departure always restores the pool and slot table, which is what makes long sessions leak-free by construction.

Decoded-pad routing places video in its quadrant:

gint w = WIDTH/2, h = HEIGHT/2;
gint x = (idx % 2) * w, y = (idx / 2) * h;
g_object_set(comp_pad, "xpos", x, "ypos", y, "width", w, "height", h,
             "zorder", (guint)(idx + 10), "sizing-policy", 1, NULL);

1.4 Temporal Queuing & the Absolute Drop Policy

Buffer-count and byte limits are semantically poor for variable-size video; the discipline is pure temporal bounds: 

max-size-time    = 300000000   /* 300 ms window   */
max-size-buffers = 0
max-size-bytes   = 0
leaky            = downstream   /* jettison the oldest, instantly */
  • Older frames are dropped the instant the window is exceeded — trading recording fidelity for live continuity is non-negotiable.
  • Queues are asynchronous thread boundaries; they are injected aggressively before encoders, sinks, and test sources, and I/O-bound sinks run async=false sync=false. A blocking filesink can therefore never stall the compositor or bend the master clock.
  • Micro-queues on generators (videotestsrc = 1 buffer, audiotestsrc = 5) give decoupling without semantic delay.
  • Timestamp regression at a queue push is refused, not dropped — the ascending PTS invariant of the queue is part of the contract, checked in the oracle's check_q.

1.5 Timestamp Monotonicity: Dilation & Interpolation

Dilation ("slow motion") happens when a CPU-bound compositor cannot sustain the declared framerate while downstream still stamps theoretical times. The remedy is capacity matching: request the framerate the hardware can guarantee (30 → 15 fps: period 33.3 ms → 66.6 ms) so stamps equal wall-clock time; the oracle models this as corrected_stamp capacity i = i * capacity with dilation_ratio = capacity / declared.

Isochronous interpolation: WebRTC senders throttle; the compositor demands a constant feed. videorate plus a strict capsfilter immediately post-decode duplicates frames (interpolate src_pts dst_period) so the grid never starves, without adding latency. The proofs: accum_is_monotone, dilate_preserves_monotone, outputs_never_ahead — interpolated output is monotone and never stamped ahead of arrival.

Telemetry closes the loop: rtprecv jitter/late/sequence-gap stats, timestamping-mode=skew, and RTCP SR/RR, NACK, PLI under the avpf profile. RTP sequence arithmetic is 16-bit modular (seq_next, diff16) with the wrap-boundary rule jb_full at span ≥ 32765.

1.6 NuStream: the Hard Real-Time End of the Continuum

NuStream keeps the pipeline abstraction and deletes every non-deterministic element of GStreamer — dynamic plugins, GObject, runtime allocation, caps negotiation. Its eight hard requirements: static WCET analysis on critical paths, zero runtime allocation in the data plane, fixed memory footprint, static topology, RTOS priority/deadline integration, pure C99, zero-copy buffer references, and auditability for formal methods. Every element carries its real-time contract as first-class data (rt_attrs_t) visible to the scheduler and to analysis tools — the same discipline that made B-Core's static tables provable.

setup_peervoid

Executes the six ordered join steps for a new peer id; every intermediate failure unwinds to the pre-join state (no half-held grid slots). The inverse cleanup_peer performs the six-stage teardown and releases the slot.

static int pay_chain(rt_element_t *e, rt_pad_t *in, rt_buffer_t *b) {
