1.6 Файлова система та менеджер файлів (File Management)

1.6.1 Огляд підсистеми управління файлами (Overview)

Загальний огляд

Підсистема управління файлами визначає логічну структуру файлової системи на фізичних носіях інформації (дискетах FD, жорстких дисках HD, флеш-носіях) та надає повний набір системних викликів ядра для роботи з файлами, записами та посиланнями.

Фізичні та низькорівневі структури даних файлової системи залежать від реалізації ядра, проте для змінних носіїв (таких як дискети чи картки пам'яті) деталі фізичної структури чітко регламентуються специфікацією для забезпечення сумісності між різними пристроями та системами.

Файлова система BTRON побудована на основі Реально-Віртуальної об'єктної моделі (Real/Virtual Body Model) і має наступні фундаментальні особливості:

  • Організація у формі потоку записів (Record Stream): кожен файл являє собою послідовність впорядкованих записів змінної довжини.
  • Мережева система посилань (Віртуальних об'єктів): між файлами формується довільна мережа посилань без використання класичних каталожних директорій.
  • Прямий доступ через посилання: доступ до файлів здійснюється безпосередньо через посилання-дескриптори.
  • Багаторівнева система прав доступу: авторизація та захист ресурсів на рівні користувачів та груп.

Файли можуть використовуватися кількома користувачами у різний час або одночасно у мережевому середовищі. З цієї причини підсистема файлового менеджера надає деталізований контроль прав доступу та високий рівень захисту даних.

Файли (Реальні об'єкти) та Посилання (Віртуальні об'єкти)

Файл (Реальний об'єкт) є контейнером для збереження даних або самими збереженими даними. Один файл складається із послідовності впорядкованих записів змінної довжини.

Посилання (Віртуальний об'єкт) є вказівником для доступу до файлу. Посилання об'єднує дані, що вказують на цільовий файл, та атрибути візуального відображення посилання.

Посилання зберігається у вигляді окремого запису всередині будь-якого файлу. На один і той самий файл може вказувати довільна кількість посилань, завдяки чому формується довільна мережева структура зв'язків між файлами.

У контексті Реально-Віртуальної об'єктної моделі файл точно відповідає Реальному об'єкту, а посилання — Віртуальному об'єкту. Віртуальний об'єкт слугує графічним представленням посилання на екрані користувача.

Оскільки доступ до файлів здійснюється безпосередньо через посилання, ім'я файлу не має абсолютного значення у системі і слугує лише текстовим ключем для пошуку. Файлу можна призначити будь-яке ім'я довжиною до 20 символів TRON Code, причому у системі дозволене існування кількох файлів із однаковими іменами.

1.6.2 Архітектура та структура файлової системи (Volume Architecture)

Файлова система (Том / Volume)

Файлова система (Том) являє собою єдину фізичну одиницю управління файлами, яка створюється на конкретному носії інформації та має фізично обмежений розмір:

  • Дискета (FD)
  • Жорсткий диск або його окремий логічний розділ (Partition HD / Flash)

Кожна файлова система обов'язково містить один Кореневий файл (Root File). Переходячи за посиланнями, що містяться у кореневому файлі, можна дістатися до будь-якого файлу даного тома. У Реально-Віртуальній моделі кореневий файл відповідає Пристроєвому об'єкту (Device VObject).

Зв'язки між файлами за допомогою посилань зазвичай визначаються в межах однієї файлової системи. Проте для посилання на файли, що розташовані на інших томах, використовується спеціальний механізм Опосередкованих посилань (Indirect Links). При використанні опосередкованих посилань цілісність зв'язку при змінах на іншому томі не гарантується, тому наявність цільового файлу потребує додаткової перевірки.

При формуванні файлової системи їй призначаються Назва файлової системи та Назва фізичного пристрою.

Монтування та підключення тома (Volume Mount/Connect)

При старті операційної системи файлові системи не підключені за замовчуванням. Для початку роботи з носієм необхідно виконати операцію підключення тома (Mount).

Підключення здійснюється шляхом вказівки логічного імені пристрою та імені підключення (Mount Name). Назва підключення є ідентифікатором тома довжиною до 8 символів і використовується як абсолютний шлях до кореневого файлу тома.

1.6.3 Внутрішня структура файлів та записів (File & Record Structure)

Типи файлів

У системі BTRON3 виділяють 2 основні типи файлів (коли вживається термін «файл», за замовчуванням мається на увазі Ззвичайний файл):

1. Ззвичайний файл (Regular File) :
Контейнер для збереження довільних прикладних та системних даних.
2. Файл посилання (Link File) :
Спеціальний файл, що слугує для опосередкованого адресування файлу на іншому томі/файловій системі. Таке посилання називається Опосередкованим посиланням (Indirect Link).

Фізичні пристрої (дискети FD, жорсткі диски HD, принтери, роз'єми послідовного зв'язку) не репрезентуються як звичайні файли в каталозі, а керуються як незалежні системні пристрої за допомогою Менеджера пристроїв (Device Manager) та унікальних системних імен.

Структура звичайного файлу

Ззвичайний файл складається із послідовності впорядкованих записів змінної довжини — Потоку записів (Record Stream). Кожен окремий запис містить 4 обов'язкові елементи:

  • Тип запису (Record Type): 8-бітне ціле число (0 – 31).
  • Субтип запису (Record Subtype): 16-бітне ціле число для додаткової класифікації або ключових слів.
  • Розмір тіла запису (Record Size): 32-бітне ціле число, що вказує довжину тіла запису у байтах.
  • Тіло запису (Record Body): Послідовність байтів даних довжиною у Record Size байтів.

Типи записів (Record Types 0 – 31):

Тип 0: Запис посилання (Link Record / Віртуальний об'єкт) :

Зберігає посилання на інший файл (структура LINK розміром 52 байти). Вміст цього запису обробляється безпосередньо файловим менеджером ядра, а прямі прикладні модифікації обмежені.

Типи 1 – 31: Записи даних (Data Records) :

Записи користувацьких та прикладних даних. Файловий менеджер ядра розглядає вміст цих записів як довільний потік байтів без аналізу їхнього внутрішнього формату.

Розмір тіла запису вказує на кількість байтів у тілі запису. Для Записів посилань (Тип 0) розмір буфера введення/виведення відповідає розміру структури LINK (52 байти), проте цей розмір не зараховується до загального обсягу користувацьких даних файлу (f_size).

Номери записів та Поточний запис (Current Record Pointer)

Записи у файлі нумеруються послідовними цілими числами починаючи з 0 (Перший запис має номер 0). Номер запису відповідає його порядковому місцю у файлі і динамічно змінюється при вставці або видаленні записів.

Після останнього запису файлу віртуально існує Кінцевий запис (End Record). Якщо файл містить N записів, Кінцевий запис має номер N.

Для кожного відкритого файлу ядро підтримує покажчик Поточного запису (Current Record Pointer), на який спрямовуються операції читання та запису. Покажчик можна переміщувати за номером запису чи за допомогою пошуку запису відповідного типу.

Структура файлу посилання (Link File Architecture)

Файл посилання створюється для опосередкованого адресування файлів на сторонніх томах. Він не містить прикладних даних користувача, а зберігає лише системні метадані посилання:

  • ID цільового файлу (f_id)
  • Прикладний тип цільового файлу (f_atype)
  • Назва цільового файлу (f_name)
  • Дата та час створення цільового файлу (rf_ctime)
  • Назва файлової системи / тома цільового файлу (fs_name)
  • Назва фізичного пристрою цільового файлу (fs_locat)

1.6.4 Права доступу та захист файлів (Access Control & Security)

Система захисту файлів

Система доступу регламентує права процесів на читання, запис та виконання файлів. Авторизація здійснюється шляхом порівняння параметрів користувача процесу з матрицею прав доступу, збереженою у метаданих файлу.

Інформація про користувача (User Context)

Контекст користувача процесу містить наступні поля:

  • Ім'я користувача (12 символів) + Приховане ім'я (2 символи)
  • Основна група 1 (12 символів) + Прихована група 1 (2 символи)
  • Додаткова група 2 (12 символів) + Прихована група 2 (2 символи)
  • Додаткова група 3 (12 символів) + Прихована група 3 (2 символи)
  • Додаткова група 4 (12 символів) + Прихована група 4 (2 символи)
  • Рівень привілеїв користувача (0 – 15, де 0 — найвищий рівень)
  • Мережевий рівень привілеїв (1 – 15, де 1 — найвищий рівень)

Права доступу до файлу (File Access Permissions)

Метадані кожного файлу містять наступні налаштування доступу:

  • Власник файлу (12 символів) + Приховане ім'я (2 символи)
  • Група власника файлу (12 символів) + Прихована група (2 символи)
  • Матриця доступу RWE:
    • Права власника (Owner RWE): Права читання (R), запису (W) та виконання/пошуку (E) для власника.
    • Рівень доступу групи (Group Level): Мінімальний рівень привілеїв користувача (0 – 15) в межах групи для прав RWE.
    • Загальний рівень доступу (Public Level): Мінімальний рівень привілеїв для всіх інших користувачів системи.
  • Спеціальні атрибути захисту:
    • Атрибут захисту від запису (Write Protect): повна заборона модифікації вмісту файлу для всіх користувачів.
    • Атрибут захисту від видалення (Delete Protect): повна заборона видалення файлу. 
    R -- Дозвіл на читання даних файлу (Read)
    W -- Дозвіл на запис та зміну файлу (Write)
    E -- Дозвіл на виконання файлу або пошук посилань у ньому (Execute/Search)

1.6.5 Операції над файлами та покажчики (File Operations)

Прикладний процес взаємодіє з файлом шляхом його відкриття системним викликом opn_fil(), який повертає дескриптор відкритого файлу. Операції читання/запису даних виконуються відносно Поточного запису (Current Record Pointer).

1.6.6 Метадані та атрибути файлів (File Metadata)

Метадані файлу зчитуються викликом fil_sts() у структуру F_STATE та включають атрибути доступу, розміри, часові мітки та кількість посилань.

1.6.8 Системні виклики файлової системи (File System Calls)

get_lnk
 
Отримання посилання на файл (Get File Link)

【Синтаксис / Прототип】

WERR    get_lnk(TC *path, LINK *lnk, W mode)

【Параметри】

TC      *path   Шлях до об'єкта у файловій системі (NULL — поточний робочий файл)
LINK    *lnk    Буфер для збереження отриманого посилання (Вихід)
W        mode   Режим отримання посилання: (F_NORM || F_BASED) | [F_DIRECT]

【Значення, що повертається】

= 0      Успішне виконання (Отримано посилання на звичайний файл)
= 1      Успішне виконання (Отримано посилання на файл посилання)
= 2      Успішне виконання (Отримано пряме посилання на цільовий файл при F_DIRECT)
< 0      Помилка (Код помилки)

【Детальний опис】

Зчитує системне посилання LINK на файл, вказаний текстовим шляхом path. Якщо path дорівнює NULL, повертає посилання на поточний робочий файл процесу. При режимі F_DIRECT повертає пряме посилання на цільовий файл.

【Коди помилок】

ER_ACCES   : Відсутні права виконання/пошуку (E) для елементів шляху.
ER_ADR     : Неприпустима адреса вказівника path або lnk.
ER_FNAME   : Некоректний, порожній або занадто довгий шлях path.
ER_IO      : Помилка введення/виведення фізичного пристрою.
ER_NOFS    : Файлова система вказаного шляху не підключена.
ER_NOEXS   : Файл за вказаним шляхом відсутній.
ER_NOSPC   : Недостатньо пам'яті ядра.
ER_PAR     : Некоректний режим mode.
chg_wrk
 
Зміна поточного робочого файлу (Change Working File)

【Синтаксис / Прототип】

ERR     chg_wrk(LINK *lnk)

【Параметри】

LINK    *lnk    Вказівник на новий робочий файл (NULL — скинути робочий файл)

【Значення, що повертається】

= 0      Успішне виконання
< 0      Помилка (Код помилки)

【Детальний опис】

Встановлює вказаний файл lnk як новий поточний робочий файл процесу. Для успішного виконання процес повинен мати права виконання/пошуку (E) на цей файл.

【Коди помилок】

ER_ACCES   : Відсутні права виконання/пошуку (E) на файл lnk.
ER_ADR     : Неприпустима адреса вказівника lnk.
ER_IO      : Помилка введення/виведення пристрою.
ER_NOEXS   : Вказаний файл lnk відсутній.
ER_NOFS    : Файлова система файлу lnk не підключена.
ER_NOSPC   : Недостатньо оперативної пам'яті ядра.
cre_fil
 
Створення звичайного файлу (Create Regular File)

【Синтаксис / Прототип】

WERR    cre_fil(LINK *lnk, TC *name, A_MODE *mode, UH atype, W opt)

【Параметри】

LINK    *lnk    Буфер для збереження посилання на створений файл (Вихід)
TC      *name   Ім'я файлу (до 20 символів TRON Code)
A_MODE  *mode   Матриця прав доступу (NULL — стандартний режим)
UH       atype  Прикладний тип додатка
W        opt    Режим створення: F_FLOAT || F_FIX || F_FILEID

【Значення, що повертається】

> 0      Успішне виконання (Дескриптор відкритого файлу fd)
< 0      Помилка (Код помилки)

【Детальний опис】

Створює новий звичайний файл на томі вказаного об'єкта lnk, встановлює атрибути доступу mode та відкриває файл для оновлення (Update). Повертає дескриптор відкритого файлу fd.

【Коди помилок】

ER_ACCES   : Відсутні права запису (W) у батьківському файлі (при F_FIX).
ER_ADR     : Неприпустима адреса вказівника lnk, name або mode.
ER_BUSY    : Батьківський файл заблокований у монопольному режимі.
ER_EXS     : Файл з вказаним ID вже існує (при F_FILEID).
ER_FNAME   : Неприпустиме або порожнє ім'я name.
ER_IO      : Помилка введення/виведення пристрою.
ER_LIMIT   : Перевищено ліміт відкритих файлів у системі.
ER_NODSK   : Недостатньо вільного місця на диску/томі.
ER_NOEXS   : Батьківський файл відсутній (при F_FIX).
ER_NOFS    : Файлова система тома не підключена.
ER_NOSPC   : Недостатньо пам'яті ядра.
ER_PAR     : Некоректний параметр opt або mode.
ER_RONLY   : Том або файл перебуває у режимі лише для читання.
opn_fil
 
Відкриття файлу (Open File)

【Синтаксис / Прототип】

WERR    opn_fil(LINK *lnk, W o_mode, TC *pwd)

【Параметри】

LINK    *lnk    Вказівник на відкривний файл
W        o_mode Режим відкриття: (F_READ || F_WRITE || F_UPDATE) | [F_EXCL || F_WEXCL]
TC      *pwd    Пароль доступу (NULL — без пароля)

【Значення, що повертається】

> 0      Успішне виконання (Дескриптор відкритого файлу fd)
< 0      Помилка (Код помилки)

【Детальний опис】

Відкриває файл lnk у вказаному режимі o_mode (читання, запис або оновлення) та повертає системний дескриптор відкритого файлу fd. Покажчик поточного запису встановлюється на перший запис файлу.

【Коди помилок】

ER_ACCES   : Відсутні права доступу для вказаного режиму o_mode.
ER_ADR     : Неприпустима адреса вказівника lnk або pwd.
ER_BUSY    : Файл заблокований іншим процесом у монопольному режимі.
ER_IO      : Помилка введення/виведення пристрою.
ER_LIMIT   : Перевищено ліміт відкритих файлів у системі.
ER_NOEXS   : Вказаний файл lnk відсутній.
ER_NOFS    : Файлова система тома не підключена.
ER_NOSPC   : Недостатньо пам'яті ядра.
ER_PAR     : Некоректні параметри o_mode.
ER_PWD     : Вказаний пароль pwd не відповідає паролю файлу.
ER_RONLY   : Том або файл перебуває у режимі лише для читання.
cls_fil
 
Закриття файлу (Close File)

【Синтаксис / Прототип】

ERR     cls_fil(W fd)

【Параметри】

W   fd  Дескриптор відкритого файлу

【Значення, що повертається】

= 0      Успішне виконання
< 0      Помилка (Код помилки)

【Детальний опис】

Закриває відкритий файл fd та вивільняє пов'язані з ним системні ресурси. При завершенні процесу всі його відкриті файли закриваються автоматично.

【Коди помилок】

ER_FD      : Вказаний дескриптор файлу fd відсутній або закритий.
ER_IO      : Помилка введення/виведення пристрою.
del_fil
 
Видалення файлу (Delete File)

【Синтаксис / Прототип】

WERR    del_fil(LINK *org, LINK *lnk, W force)

【Параметри】

LINK    *org    Батьківський файл (NULL — без батьківського файлу)
LINK    *lnk    Видаляється файл
W        force  Прапорець примусового видалення

【Значення, що повертається】

>= 0     Успішне виконання (Кількість посилань із лічильником 0)
< 0      Помилка (Код помилки)

【Детальний опис】

Вилучає запис посилання на файл lnk із батьківського файлу org та зменшує лічильник посилань. Якщо лічильник посилань досягає 0, файл фізично видаляється з носія.

【Коди помилок】

ER_ACCES   : Відсутні права запису (W) у батьківському файлі org.
ER_ADR     : Неприпустима адреса вказівника org або lnk.
ER_BUSY    : Файл відкритий або використовується як робочий файл іншим процесом.
ER_IO      : Помилка введення/виведення пристрою.
ER_NOEXS   : Файл org або lnk відсутній.
ER_NOFS    : Файлова система тома не підключена.
ER_PERM    : Файл має атрибут захисту від видалення (Delete Protect).
