CLU コマンド (BTRON Commands)

CLU ツール群 · BTRON3 3.20 準拠 · 独立 ELF 形式 · NASA/JPL Power of Ten
BTRON3 実身／仮身マルチレコード体系に最適化されたネイティブ CLI コマンド仕様
"High-assurance native POSIX & CLU command suite implemented as standalone ELF binaries."
← アプリケーション一覧 (Applications Index)
CLU コマンド（BTRON Commands / CLU Suite） — B-Systemの仕様に準拠したC99実装のネイティブコマンドラインユーティリティ群。BusyBoxやchimerautils等の汎用Unix移植層に依存せず、実身（Real Body）／仮身（Virtual Body）マルチレコード構造を直接駆動するゼロヒープ・決定論的ツールスイート。
"Official technical specification for the native CLU/POSIX application suite within the B-System operating environment."

概要 (Overview)

B-System CLU（Command Line Utilities）ツール群は、POSIX標準の操作感を保ちながら、BTRON3実身／仮身ネットワーク型ファイルシステムを直感的に操作するためにゼロから設計されたネイティブC99コマンド群です。 各コマンドは将来的に独立したワンショットELF実行バイナリ（/SYS/bin/*.elf）として配置・実行されるアーキテクチャを持ち、MIPS R5900 (PS2)、ARM32/ARM64 (Raspberry Pi)、x86_64、M68kの全CPUコアで同一の決定論的動作を保証します。

1. なぜBusyBoxやchimerautilsではなくネイティブBTRONアプリを採用したのか
(Architectural Rationale: Native BTRON vs. BusyBox / chimerautils)

B-Systemの設計において、一般的な組込みLinuxで用いられる BusyBox や BSD系ツール集 chimerautils をそのまま移植するのではなく、独自のネイティブCLUツール群を構築した理由は、以下の4つの決定的なアーキテクチャ要件に基づいています。

比較項目 (Evaluation Criteria) B-System ネイティブ CLU BusyBox / chimerautils
ファイルシステムモデル (FS Model) BTRON 実身／仮身マルチレコード (B-FS / TAD)
1つの実身内に複数のレコード（データ、属性、ハイパーリンク、実行バイナリ、ベクトル埋め込み）を保持。opn_fil, opn_rec, fil_get_rec_link_info 等のTRON VFS APIを直接駆動。		 フラットな単一ストリーム POSIX Inode
Unixの単一バイトストリームモデルを前提としており、BTRONのマルチレコード構造やハイパーメディアリンクを透過的に認識・操作できない。
安全基準と決定性 (Safety & Determinism) NASA/JPL "Power of Ten" 厳格準拠
実行時の動的ヒープ割当禁止（静的メモリバッファ運用）、全ループの上限固定、有界再帰深さ（<16）、エラー戻り値の100%検証。		 未拘束のヒープ消費 (malloc/realloc 多用)
動的メモリ再確保や未拘束の再帰が多く、組込みスタック（8KB〜64KB）環境や低メモリ環境（PS2 32MB RDRAM）で意図せぬクラッシュを引き起こす。
OS依存性とランタイム (OS Dependencies) 純粋 C99 フリースタンディング (Zero Host Portaling)
libc_shim.h と T-Kernel / BTRON コアのみで動作。fork/execve、Unixシグナル、pthreads、/proc、/dev などのUnix擬似抽象化レイヤを一切必要としない。		 重厚な POSIX エミュレーション層が必要
glibc/musl、Unixドメインソケット、procfs、シグナルハンドリングを要求し、カーネル空間に巨大なオーバーヘッドと脆弱性境界をもたらす。
多言語文字コード (Multilingual TRON Code) TRON Code & UTF-8 ネイティブ対応
ファイル名やレコードヘッダ内の2バイトTRONコード、漢字、チベット文字、仮名文字を外部ロケールファイルなしでネイティブ展開。		 Unix ロケール (setlocale / glibc gconv) 依存
TRON文字体系を解釈できず、文字化けや名前解決の不整合が発生する。

2. コマンド仕様体系 (CLU Command Reference)

CLUツール群は、BTRONの実身レコード構造を操作するためのPOSIX互換コマンドおよび拡張コマンドで構成されています。

コマンド 構文 (Syntax) 機能説明 (Description) 実装ファイル (C99 Source)
ls ls [-l|-t] [path] 実身一覧の表示。属性（ATYPE/ATR）、レコード数、総サイズ、タイムスタンプ、ELF/実行フラグに応じたカラー表示。 src/clu/ls.c
fs fs [-l|-a|-g|-t|-r] [target] 実身レコードインデックス構造および引き出し（Drawer）木構造グラフの完全検証・ダンプ。 src/clu/fs.c
stat stat <file|FID> 実身のブロック配置、DID/PDID、レコードメタデータ、TRONコード文字列の完全詳細診断。 src/clu/st.c
cp cp <src> <dst> 実身の全レコード複製（マルチレコード構造、属性、ペイロード完全保持）。 src/clu/cp.c
mv mv <old> <new> 実身の移動および名称変更（アトミックなボリューム更新とキャッシュ同期）。 src/clu/mv.c
rm rm <path> 実身の削除（所属ブロックの回収およびリンク整合性更新）。 src/clu/rm.c
ln ln <src> <linkname> ハイパーメディア仮身レコード（RT_LINK）の生成。 src/clu/ln.c
df df [volume] マウント済みボリュームの総ブロック数、空き容量、使用率、最大FID数の表示。 src/clu/df.c
sync sync 全マウントボリュームのダーティブロックおよびFIDテーブルキャッシュをディスクへ完全フラッシュ。 src/clu/df.c
tp tp [-x|-a] <file> 実身レコードの内容出力（TAD文書セグメント展開、ELFプレビュー、16進数/ASCIIダンプ）。 src/clu/tp.c
cd cd [/SYS|path] カレントワーキングボリュームおよび実身パスの切り替え。プロンプト自動同期。 src/clu/fs.c
mkf mkf <path> 新規実身レコードコンテナの生成。 src/clu/fs.c
empf empf <path> 実身内の全レコード削除（ヘッダを保持した初期化）。 src/clu/rm.c
chmod chmod -a# <path> 実身保護属性（書込禁止・削除禁止）の動的変更。 src/clu/st.c
touch touch <path> 実身のアクセス／変更日時の現在時刻更新（存在しない場合は空実身生成）。 src/clu/st.c

3. 独立 ELF バイナリ実行モデル (External ELF Execution Model)

B-System では将来的に、すべての CLU コマンドおよびワンショットアプリケーション（Quake, Sokhatsky Commander, Terminal Vision, GLGears, XMB, Demoscene 等）をカーネル内静的リンクから分離し、独立した ELF 32/64-bit 実行バイナリ として実行するアーキテクチャを採用します（詳細は doc/txt/ELF.txt 参照）。

  • ストレージ形式: B-FS ボリューム内の RT_PROG（実身種別 9）レコードに ELF バイナリが直接格納されます。
  • ロード・実行パイプライン: exec_elf() が ELF プログラムヘッダ（PT_LOAD）を解釈し、仮想メモリページをマップしてエントリポイントへジャンプします。
  • メモリ分離と安全性: 各コマンドは独立したタスク空間で実行され、実行完了とともに全リソースが自動解放されます。
