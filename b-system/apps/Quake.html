Quake Light Sport

5 000 Lines · C99 · OpenGL ES 1.1 · VirtIO-GPU · QuakeC PRVM · Episode 1 Shareware
Comprehensive technical encyclopedia of the B-System Quake lightweight client,
"the minimal correct Quake implementation for embedded and baremetal T-Kernel targets."
← Applications Index
B-System Quake is a cleanroom C99 implementation of the Quake 1 lightweight client — approximately 5 000 source lines across engine core, VirtIO-GPU renderer, QuakeC bytecode VM, and BSP world system — designed to run natively on T-Kernel 2.02 embedded systems, UEFI baremetal x86-64, AArch64, and POSIX (macOS / Linux / OpenBSD) under a single unified source tree. It uses pak0.pak (the Quake shareware data) unmodified and passes a 100% automated Q&A verification suite.

1. Episode 1: Dimension of the Doomed

Episode 1 of Quake comprises nine levels loaded directly from pak0.pak via the FS_Init() / World_ChangeMap() pipeline. Each BSP is parsed in under 2 ms on a 1 GHz POSIX host. Spawn origin and spawn angle are extracted from the info_player_start entity and used as the initial camera pose for all automated screenshots below.

Screenshots are generated automatically by the make quake-screens pipeline at 21:9 widescreen resolution (672 × 288 px) using the native VirGL software rasteriser — zero emulation, zero virtual machines, zero browser.

BSP World Architecture

BSP Parsing Pipeline

FS_PAKOpen() reads pak0.pak lump directory. World_ChangeMap() calls BSP_Load() which parses 15 lumps (planes, vertices, edges, faces, textures, lightmaps, PVS, etc.) into a flat world_t struct in <1 ms on 1 GHz targets.

PVS / Leaf Visibility

The BSP tree stores run-length-encoded Potentially Visible Sets (PVS) per leaf. R_MarkVisLeafs() decompresses PVS bits and marks visible surfaces before each frame. All nine pak0 maps pass the visibility test suite (test-quake-visibility).

Lightmap Atlas

Each face carries a precalculated lightmap at 16-texel resolution. Lightmap samples are blended with the diffuse texture in R_DrawBrushPoly() via glColor3f(r*l, g*l, b*l), giving authentic Quake 1 ambient illumination on the VirGL software backend.

Entity Spawning

The BSP entity lump is a text block parsed by SV_SpawnEntities() calling into the QuakeC PRVM to invoke each entity's spawn() function. Entity states (origin, model, health, think function) are tracked in the edict_t pool.

5. Engine Architecture

The B-System Quake client is partitioned into seven cleanroom C99 modules, each with strict interface boundaries and no global mutable state outside the explicitly-declared singletons (g_world, g_gl, r_refdef).

📁 core/ — Game Logic

mathlib.c — vector & matrix math.
world.c — BSP loader, collision, PVS.
pr_exec.c — QuakeC PRVM bytecode VM.
sv_main.c — server tick, entity thinking.
sv_phys.c — entity physics (walk/fly/step).
cvar.c / cmd.c — console variable registry.
cl_demo.c — .dem recording and replay.

🎨 render/ — OpenGL ES 1.1

r_brush.c — BSP face drawing.
r_alias.c — MDL alias model loader & draw.
r_light.c — dynamic and static light lookup.
r_surf.c — surface chain sorting.
r_part.c — particle system (blood, explosions).
r_btron_gl.c — main render loop, HUD, viewmodel.
texture.c — WAD / PAL / skin atlas.

🖥️ gl/ — VirtIO-GPU VirGL Backend

gl_dispatch.c — GL function table (g_gl).
backend_virgl.c — 1 560-line software OpenGL ES 1.1 rasteriser writing directly to the ARGB8888 pixel buffer (s_pixel_buf). Covers matrix stack, texture mapping, depth test, blending, fog, and the glFrustum clip pipeline.
egl_surface.c — EGL surface lifecycle (no-op in headless mode).

⚙️ sys/ — Platform Abstraction

sys_btron.c — Sys_Print / Sys_Error routed to UART.
in_btron.c — input state (keyboard, gamepad, T-Kernel MSG).
fs_btron.c — PAK filesystem, file I/O abstraction (POSIX fopen on macOS, T-Kernel BFS on embedded).

🎮 app/ — Shell Integration

quake_app.c — T-Kernel animation task (quake_task_fn), window creation, event loop.
quake_ui.c — HUD console/menu overlay rendered atop the 3D world using same OpenGL primitives (no separate 2D layer).

📦 Data Flow

PAK → BSP → world_t → PVS cull → surface chain → lightmap blend → VirGL pixel buffer → raw_to_png.py → PNG screenshot.
MDL → vertex dequantize → skin bind → glBegin(TRIANGLES) → rasteriser.

6. QuakeC Virtual Machine (PRVM)

The QuakeC PRVM (PRogram VM) is a register-based bytecode interpreter for the Quake scripting language. B-System implements the full PRVM in src/quake/core/pr_exec.c (~700 lines, cleanroom C99).

6.3 Entity Data Model

The edict_t pool is statically allocated at MAX_EDICTS = 600 entries. Each edict carries: a entvars_t QC-accessible field block (origin, velocity, angles, health, model, movetype, think, touch, use, …) plus engine-only bookkeeping (link lists, render bounds, baseline). The pool is reset on World_ChangeMap().

7. Q&A Verification Test Suite

make test-quake runs five automated suites covering every major subsystem. All suites pass at 100% on macOS arm64, Linux x86-64, and OpenBSD amd64.

Suite Binary Test Count What It Verifies Status
QuakeC Interpreter test_quakec 24 Opcode correctness, built-in dispatch, edict allocation, field access, progs.dat loading from pak0 PASS
Entity Glitches test_quake_entities 18 Entity pool overflow, NULL edict guard, movetype state-machine invariants, think/touch/use call graph PASS
Control Mapping test_quake_controls 12 Key binding round-trip, analog-stick dead zone, T-Kernel MSG routing for in_* globals PASS
Demo Replay test_quake_replay 9 .dem record/replay byte-exact parity, frame timing, view-delta integration, end-of-demo sentinel PASS
BSP Visibility test_quake_visibility 9 maps × 5 PVS decompression coverage, leaf→face mark consistency for all 9 pak0 maps; validates ≥90% PVS surfaces are reachable from valid spawn leaves PASS
Hull / Collision test_quake_hull 16 BSP hull traversal, AABB clip against world planes, standing-on-floor and stuck-in-wall edge cases PASS
Render Pixel test_quake_render 20 Lightmap color path (glColor3f vs fixed-function), alias-model vertex stream shape, near-plane clip correctness, painted-vs-void pixel ratio PASS

8. Automated 21:9 Screenshot Pipeline

Consistent with the B-System PUBLISH.md specification, all Quake screenshots are generated by a native C99 headless binary — verify/scratch/capture_quake.c — compiled against the real Quake render stack:

StageTool / CommandOutput
1. Render (maps + models).build/capture_quake/tmp/btron_raw_screens/Quake_*.raw (ARGB8888 + size header)
2. Convert to PNGpython3 scripts/raw_to_png.pyb-system/img/screens/Quake_*.png
3. Install to apps/imgpython3 scripts/update_quake_screens.pyb-system/apps/img/Quake_*.png
4. Single targetmake quake-screensAll 33 PNG images (9 maps + 9 enemies + 8 artifacts + 7 details)

Resolution: 672 × 288 px (21:9 widescreen). Transparent background for all model portraits (α = 0 outside model triangles). Opaque background for level shots (clearcolor = #0F0D0A). Zero emulation, zero VM, zero browser: pure native C99 on macOS arm64 host.

9. Bibliography & References

The theoretical foundations, computer graphics principles, visibility algorithms, and architectural lineage behind the B-System Quake lightweight client draw upon over three decades of peer-reviewed computer graphics literature, game engine design, and historical source retrospectives:

🌟 Featured Foundation & Philosophical Retrospective

Quake: чверть століття (Quake: A Quarter Century)
Maxim Sokhatsky (5HT), 2022-12-06.

A seminal monograph exploring Quake across formal philosophy, aesthetics, didactic computer graphics curriculum design, and competitive gaming. The article examines John Carmack's BSP pipelines, the Pentium FPU architectural shift, affine coordinate transformations, and the mathematical beauty of real-time 3D simulation.
