B-Video: Display Path & Video Playback Contract

From a painted pixel to a presented picture: the VirtIO-GPU / VESA / GDEV display stack, the unified image intake, and the demux–decode–present contract that keeps video on the proven media plane without ever touching a bitstream theory.

Scope

B-Video specifies two things that share one word. First, the shipped display path: Display-Primitives output going through VirtIO-GPU 2D resources (src/drivers/virtio/virtio.c, include/device/virtio.h, include/drivers/virtio_gpu.h), the x86 VESA framebuffer (include/drivers/vesa.h, src/drivers/vesa/), the BTRON GDEV video-mode tables (include/device/videomode.h, screen.h), NEON fast blit (include/btron/fast_blit.h), and the clean-room image decoders (src/graphics/image_decode.c). Second, the video playback architecture defined by doc/md/VIDEO.md: a frame is a NuStream buffer with a clock — a picture, a PTS, a slot from a static pool — and never a second bus.

The substrate is already proven: damage and blit live in ui_compose, the VideoCore mailbox and framebuffer pitch in drivers, pool/refcount and queue laws in media_rtp, claim/publish/drain in media_smp. What video adds is only the frame algebra on top — and its five model pairs are, as of this revision, specified but not yet proven; §Verification says exactly which.

Part 1 — Architecture & Conceptual Model

1.1 Resource → Host → Screen (the present path)

DP surface (ARGB32)
   │  vio_gpu_create_resource_2d(dev, id, FMT_B8G8R8A8_UNORM, w, h)
   ▼
guest resource ── vio_gpu_transfer_to_host_2d(offset) ──► host copy
   │
   ├─ vio_gpu_resource_flush(x,y,w,h)      damage rect → scanout
   ├─ vio_gpu_set_scanout(scanout,id,w,h)  modeset once at init
   └─ vio_gpu_sdl2_blit_frame()            host-backed ports
VESA ports: direct framebuffer writes (vesa_fill_rect / draw_window), 0x105-style init.
Pi bare-metal: BCM2711 VC4/HVS composition — GPU.txt/RENDER.txt are authoritative.

Presentation is damage-driven, and that discipline is already a theorem: outside the claimed damage rectangle the front buffer is unchanged (presenter_outside_preserves_front family in the compositor proof). The stats half of async_rt.h separates blit_us / present_us / composite_us so the UI plane can account for the pixel work as one budget charge, never three invisible ones.

Zero-copy present (R3). A YUV overlay plane that accepts NV12 makes the present a pointer swap; only RGB paths pay a blit, and that blit is charged to the UI plane budget. Video must never resize the surface: swap remains an involution on surface dimensions.

1.2 Frame Lifecycle: Demux → Decode → Present

container (tag: AVI | MP4 | MPEG_PS | ASF)
   │  demux cursor: one step yields ≤ 1 packet or a stuttering refusal
   ▼
bounded packet queue          queued + dropped + decoded = demuxed   (V2)
   │  access unit in  →  E_OK | E_AGAIN | E_DEC ; no partial picture presentable (D2)
   ▼
picture slot pool (refcounted)  ref_cap bound; last release recycles  (D1)
   │  PTS monotone; late picture dropped, never reordered             (V3)
   ▼
present clock ± slip budget     PTS ≤ clock + slip, else wait or counted drop (R1)
  • Containers are tags, not parsers. mdat offsets, AVI indexes and MPEG-PS pack headers are opaque spans; the only law is cursor' = cursor + consumed.
  • One in-flight decode (V5): a second access unit is refused or queued — never a second implicit task.
  • Seek is a segment rebasing (V6): after a seek the pool is empty and the next PTS is the new base — the same start-versus-cur algebra as the RTP theory.
  • Bitstreams are out of scope by design: no Coq model of CABAC, VC-1 bitplanes, or MPEG-2 IDCT. The theory sees access-unit receipts only.

1.3 VPU vs CPU Plane Claims

A decode is a budget claim, and the codec determines which lane may be claimed (D3/D4): H.264 may charge the VPU lane on Pi-class hardware; VC-1 and MPEG-2 are software-plane residents (720p ceiling), and a VPU claim for them is a legal refusal, not a fallback. Both paths end in the same picture record — output stride and crop in range, pitch ≥ width × bpp (the lifted vc4_fb_pitch_ge_width law). On the transport side, a stalled video plane cannot raise held on the audio ring, nor the converse (P8/S3): video overruns drop video frames and never steal the audio tail. Audio is the master clock; video slip is pts_video − pts_audio, bounded by slip_cap, resolved by dropping or repeating pictures — audio is never stretched to chase video (S1/S2).

1.4 Capture & Image Intake

Intake has one shape: files and streams become RGBA8 buffers or NuStream pictures. The clean-room decoders (decode_image_rgba family) turn PNG/GIF/JPEG into caller-owned RGBA pixel arrays; frame-grab tooling (src/tools/capture_*.c) exercises the same flush path the compositor uses; the WebRTC ingest path (per-peer decodebin → I420 caps → jitter window) is specified in B-RTP, whose packetization laws (P1–P7) are the network-side twin of the frame algebra above.

Part 3 — API Reference

3.1 VirtIO-GPU (2D present surface)

vio_gpu_*vio_status_t

The five-call resource lifecycle: init, mint a 2D resource, copy guest pixels up, flush a damage rectangle to the scanout, and (host-backed ports) blit a whole frame.

vio_status_t vio_gpu_init(struct vio_gpu_device **out_dev); vio_status_t vio_gpu_create_resource_2d(dev, uint32_t resource_id, uint32_t format, uint32_t width, uint32_t height); vio_status_t vio_gpu_transfer_to_host_2d(dev, resource_id, x, y, w, h, uint64_t offset); vio_status_t vio_gpu_resource_flush(dev, resource_id, x, y, w, h); vio_status_t vio_gpu_set_scanout(dev, scanout_id, resource_id, width, height); vio_status_t vio_gpu_sdl2_blit_frame(dev, const void *src_buf, size_t buf_size);
CallPreconditionPostcondition
create_resource_2did unused; w,h ≤ max mode.Resource exists in NULL state; no pixels valid yet.
transfer_to_host_2dResource live; rect inside extent.Host copy of the rect; resource UNCOMMITTED.
resource_flushTransfer completed for that rect.Scanout pixels inside rect updated; outside untouched (damage law).
set_scanoutResource sized to scanout.Modeset: the resource is the display's source for future flushes.

4.3 Present-clock discipline (contract sketch)

picture_t *p = decode_receipt();               /* E_OK only          */
if (!p) return;                                /* E_AGAIN / E_DEC    */
if (pts(p) > present_clock() + SLIP_US) { slot_hold(p); return; }
if (pts(p) < present_clock() - SLIP_US) { slot_release(p); counted_drop++; return; }
damage = intersect(p->rect, surface_rect);     /* R2: outside intact */
slot_release(p);                               /* last ref recycles  */

Verification Status & Roadmap (honest account)

Already proven, reusable today:

  • Compositor damage & blit algebra — ui_compose_properties.v.
  • VideoCore mailbox + vc4_fb_pitch_ge_width — drivers_properties.v.
  • Static pool/refcount/queue/PTS laws video inherits — media_rtp_properties.v.
  • Claim/publish/drain, non-blocking rcv, single drain owner — media_smp_properties.v.
  • GL surface behaviour — opengl_properties.v.

Specified, not yet proven: the five video model pairs of doc/md/VIDEO.md — media_video, media_vrtp, media_vdec, media_vpresent, media_avsync (.ml oracle + .v proof each). None of these files exist in verify/models/ at this revision, and no law in §2.2 above should be cited as Coq-closed until its pair lands. The planned oracles follow the InterCore pattern: instantiate the shipped numbers (1080p60 H.264 on VPU, 720p software ceiling, jitter depth, slip cap) and exhaustively search the small interleavings. When each pair is verified, its dossier belongs on this shelf at b-video/theorems/.
