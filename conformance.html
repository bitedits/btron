Executive Summary for Certification Bodies & Evaluators Formal Evaluation

This document is prepared specifically for technical auditors, the TRON Association, the TRON Forum, and embedded systems evaluators who demand exact, verifiable adherence to the normative BTRON 3.20 Operating System Specification (documented in the canonical Japanese/Ukrainian corpus at b-spec/os_spec/).

Core Conformance Principle: Our audit enforces strict transparency. Rather than mocking or faking 100% test passes for incomplete modules, missing subsystems (such as full vector Font Management, network socket pipelines, and real-object transaction brokers) are linkable as standard BTRON ABI stubs that explicitly return E_NOSPT (-17). The automated test suite exercises each normative requirement and honestly registers failures, ensuring evaluators see the exact boundary between operational code and pending implementation.
Level 0 Conformance
L0 — PASS (100.0%)

Fundamental data types (B, H, W, D, TC, PNT, RECT, PAT) strictly conform in size, signedness, and alignment across ARM32, AArch64, and x86_64 hosts.

Level 1 Conformance
L1 — PASS (100.0%)

100% of all 329 normative BTRON 3.20 system calls, headers, data structures, and ABI entry points are declared and linkable across all translation units.

Level 2 Conformance
L2 — 90.2% (370 / 410)

Full functional execution verified for Window Manager, HMI Controls, Display Primitives, T-Kernel RTOS, and Record Streams. 40 clauses intentionally report FAIL (E_NOSPT) for pending subsystems.

Meticulous Subsystem Analysis & Commentary

1. Fundamental Types & Memory Layout [IMPL] Conforming

Normative Reference: include/btron/types.h & Sakamura Spec §1.1–§1.3.
Evaluation: All standard TRON scalar widths (B=1, H=2, W=4, D=8, TC=2) are mapped via fixed-width stdint.h types. Signed integer promotion behavior and unsigned bit patterns match standard BTRON machine models. Geometry structs (PNT, RECT, PAT) match the 4-byte, 8-byte, and 8-byte binary layout expected by the Window Manager and Display Primitives.

2. Sakamura Window Manager (WND) [IMPL] Conforming

Normative Reference: b-spec/os_spec/shell/window.html & include/btron/wnd.h.
Evaluation: Implements authentic Sakamura compact tabs (WND_ATTR_COMPACT_TAB) and sliding title tabs (WND_ATTR_SLIDING_TAB) with horizontal drag-offsets. Includes dirty region clipping, z-order re-stacking (top_wnd), coordinate mapping, close button hit detection, and recursive repaint pipelines without desktop flicker.

3. Physical Panel HMI Components (HMI) [IMPL] Conforming

Normative Reference: b-spec/os_spec/shell/panel.html & parts.html.
Evaluation: Provides cleanroom implementations for all 10 core industrial physical controls:

  • Push Switch & Toggle Switch: Dual-bevel 3D tactile depression with touch/release edge trigger modes.
  • Standard Triad: Multi-state operational triad selector.
  • Up/Down & Radio Selector: Mutual exclusion groups with cycle boundary clamping.
  • Slider & Dial Volume: Continuous analogue parameter tuning with notch marks.
  • Bar Meter & Status LED: Real-time dynamic visual telemetry with 4-state LED signaling.
  • Digital Display & Universal Controller: 7-segment/alphanumeric numeric indicators and Enableware keypad routing (hmi_handle_universal_key).

4. Real / Virtual Object Manager (OMGR) [STUB] 15 Clauses Pending

Normative Reference: b-spec/os_spec/shell/omgr.html & include/btron/omgr.h.
Audit Comment: The underlying hypermedia data model (ROBJ / VOBJ_LINK) is operational in the kernel; however, the 54 advanced GUI Shell Object Manager syscalls (§3.8.5: oreg_vob, b_odup_vob, odel_vob, osta_prc, oput_dat, oupd_fil, etc.) and application helpers (§3.8.6: adsp_sel, adsp_slt, apnl_men, achg_bgc) are currently provided as linkable stubs returning E_NOSPT. These stubs are fully tested in v_omgr.c and accurately report failure until connected to the desktop layout engine.

5. Multilingual Font Manager (FMGR) [STUB] 13 Clauses Pending

Normative Reference: b-spec/os_spec/shell/font_mgr.html & include/btron/font_mgr.h.
Audit Comment: Bitmap font rendering for JIS X 0208 and TRON Code language planes is fully operational in src/font/jis_fonts.c and troncode.c. The formal BTRON Font Manager dynamic descriptor API (fdef_fnt, fdel_fnt, fopn_fon, fcls_fon, fset_fon, fget_img, fset_ang) is declared with complete normative data structures (FDEF, FSSPEC, FDATA) and returns E_NOSPT pending integration with scalable outline rasterizers.

6. TCP/IP Sockets Network Manager [STUB] 12 Clauses Pending

Normative Reference: b-spec/os_spec/shell/tcpip.html & include/btron/tcpip.h.
Audit Comment: The complete BTRON socket specification (so_socket, so_bind, so_listen, so_accept, so_connect, so_send, so_recv, so_select, so_gethostbyname) is linkable via src/kernel/tcpip.c and returns E_NOSPT. This provides full ABI linkability while isolating the microkernel until the VirtIO network pipeline is enabled.
