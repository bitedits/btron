ASYNC.txt — Deterministic Real-Time Input & Presentation
========================================================

B-System (BTRON 3.20)
NuttX-style scheduling constraints
Related: EVENTING.md, USB.md, GUI.md, SMP.md

Status: Design plan
Policy: Input task and UI task share the SAME priority.
        Determinism comes from bounded work, fixed periods, and zero unbounded critical sections.

0. Rooting in B-System SMP Spec (btron-smp.tex / SMP.md)
--------------------------------------------------------

B-System enforces a strict duality:

- Tier 1 – Embedded MCU (640KB..1MB, unicore, e.g. Raspberry Pi 400 GUI path):
  Single flat physical address space. MMU isolation is mathematically counterproductive
  (TLB invalidation + page-walk penalties destroy sub-µs determinism). Scheduling remains
  classical µITRON priority + cyclic handlers. Input and UI share the same priority;
  determinism is pure period + budget.

- Tier 2 – Workstation SMP (x86_64 UEFI, multi-core, src/kernel/core_smp.c 1MB..16MB):
  Hardware-enforced Ring-3 isolation via per-process PML4 + PCID, combined with
  the Erlang-inspired actor runtime:

  | Theorem (Zero-Switch Actor Topology):
  | Given an SMP machine with N symmetric cores C₁ … Cₙ, maximum message-dispatch
  | throughput with zero kernel context switches is achieved by dedicating exactly
  | N worker threads pinned to those cores, each draining a dedicated Lock-Free
  | Multi-Producer Single-Consumer (MPSC) task queue in a continuous Cloop
  | using atomic CMPXCHG8 / __atomic_exchange_n.

Display Primitives (DP) remain in Ring 0 / shared higher-half (lesson of
Windows NT 3.51 -> NT 4.0 win32k.sys). Graphics never travel through user-space IPC.

Consequently the ASYNC input/UI planes are expressed as actor messages (or
periodic cyclic workers that post to actor queues) rather than classic blocking
threads that contend for a shared cooperative loop.

0.1 InterCore Protocol (PUB / SUB / SEND / RECV / SPAWN)
--------------------------------------------------------

The concrete inter-core messaging fabric that realises the Zero-Switch Actor Topology
on Tier 2 is the InterCore bus protocol (originating in the Tachyonic / platform.rs
design; see https://github.com/o83/platform.rs and its InterCore taxonomy). It maps
directly onto the lock-free MPSC queues of core_smp.c and supplies the only permitted
cross-core primitives for ASYNC planes.

InterCore bus properties (rooted in platform.rs InterCore):

- Star topology of SPMC queues: each core owns exactly one publisher queue.
- MPSC is realised as a pure computable function over the set of publisher queues (no central broker, no kernel traps).
- poll_bus runs on every scheduler yield; any pending message addressed to the current core is handled before the next task begins.
- Zero-copy CAS multicursor ring buffers (sectors) provide the underlying transport.

Canonical API (O-language / FFI surface; identical semantics in pure C for B-System):

  pub   [capacity]                 : creates a publisher CAS cursor; returns system-wide writer Id
  sub   [publisher]                : creates a subscriber CAS cursor bound to a writer; returns reader Id
  spawn [core; program; cursors]   : creates a Task on the named core, granting exclusive ownership of the listed cursors
  snd   [writer; data]             : non-blocking send into the writer cursor (nil on success)
  rcv   [reader]                   : non-blocking receive from the reader cursor; yields to scheduler if empty

Mapping onto ASYNC planes (Tier 2):

- ACTOR_INPUT and ACTOR_UI are ordinary Tasks created by spawn on distinct (or shared) cores.
- The IRQ path (or a thin ISR-to-actor bridge) obtains a writer cursor via pub and posts EVENT_INPUT / pointer snapshots with snd.
- The consumer side of each actor drains its reader cursor(s) with rcv inside its budgeted period loop.
- Cursor ownership is transferred exclusively via the spawn argument list;
  this eliminates any shared mutable state that would require a mutex and
  therefore eliminates priority inversion between equal-priority planes.

Thus InterCore is the normative microkernel/microcore substrate for the BTRON 3.20 Process
API on real multi-core hardware with APIC. Classic T-Kernel mailbox and message-buffer APIs
remain the portable programmer-facing surface; on the critical ASYNC path they resolve
directly to InterCore primitives so that the Zero-Switch Actor Topology is preserved.

Citation: platform.rs InterCore taxonomy (Publisher / Subscriber / Spawn / Send / Receive) —
https://github.com/o83/platform.rs (intercore/index.pug / o83.github.io documentation).
The same CAS multicursor + star-topology MPSC model underpins the Zero-Switch Actor
Topology of btron-smp.tex §3.

1. Real-time goals (NuttX-like)
------------------------------

1.1 Hard requirements

  Property                   Requirement                                                                                        B-System
  -----------------------    --------------------------------------------------                                                 -----------------------------------
  Bounded ISR                xHCI / timer ISR WCET <= T_isr_max (target <= 50 us)                                               ISR only updates wait-free pointer
  No ISR -> UI               ISR must not call workbench_*, blit, heap, or unbounded snd_evt loops                              Pure message post; no shared
  Fixed input period         Pointer/HID integration on a periodic cadence (e.g. 1 ms), not "whenever the paint loop runs"      TASK_INPUT actor or cyclic handler
  Bounded input work         Each input period processes <= N event-ring TRBs and <= M HID reports (defined drop/defer policy)  Budget enforced inside worker loop
  Bounded UI work            Each UI period has a time budget; unfinished paint is deferred to the next period                  TASK_UI actor drains its MPSC queue under budget
  Equal task priority        pri(input) == pri(ui) (and present, if separate)                                                   Same priority class; periods + budgets give determinism
  Priority inheritance       Mutexes shared by input and UI must support inheritance, or use wait-free snapshots                Prefer wait-free seqlock / double-buffer (zero inversion)
  No I/O priority inversion  Full-screen CPU blit must not be a critical section that blocks HID progress                       Blit lives only inside UI/PRESENT budget; IRQs stay enabled

1.2 What equal priority does NOT mean

  Equal priority does not mean one big loop that paints for ~1 ms then
  polls USB. It means both tasks are peers under a periodic, budgeted
  schedule, while host-controller progress is driven by: 1) interrupt or a
  2) periodic tick with fixed WCET that posts a message into the appropriate
  MPSC queue of the Erlang actor topology.

2. Failure mode to eliminate
----------------------------

Non-deterministic batching: HID reports accumulate while the CPU is inside
workbench_render / blit_backbuffer_to_fb, then apply in one lump
-> saturated mouse latency.

That violates fixed input period, bounded integration latency, and
separation of short IRQ path from long UI work.

Root cause on Pi 400 GUI: a single cooperative loop owns
  (1) xhci_process_events
  (2) HID decode / pointer integration
  (3) snd_evt / get_evt
  (4) full Workbench paint + CPU framebuffer blit (~1.1 ms)

While (4) runs, (1) stalls. Reports pile up in s_accum_* or the HC sits
with only one EP1 TRB in flight.

  | Invariant (rooted in SMP paper):
  | The path that advances the USB host controller must never share
  | a blocking critical section with full-screen memory copy or desktop composite.
  | On Tier 2 this is enforced by placing input and UI on distinct
  | actor queues (or distinct cores when N ≥ 2).

3. Scheduling model
-------------------

3.1 Threads / tasks (same priority)

  Priority P (shared):
    TASK_INPUT     period Ti = 1 ms    budget Bi
    TASK_UI        period Tu = 8 ms    budget Bu   (e.g. 120 Hz class)
    TASK_PRESENT   period Tu           budget Bp   (optional; may merge with UI)

  Interrupt level (not a task priority):
    IRQ_XHCI or IRQ_TICK   WCET <= T_isr_max

  Same P => under fixed-priority preemptive RTOS they time-slice or run
  FIFO when both ready. Periods and budgets provide determinism, not
  "input always wins."

On Tier 1 MCU these are classical cyclic tasks created with identical itskpri (µITRON / T-Kernel).
On Tier 2 SMP they are realised as:
  * dedicated worker threads pinned to cores, or
  * messages enqueued via btron_mpsc_enqueue into
    the core’s private MPSC queue (see Listing in btron-smp.tex / SMP.md §3).

Same priority ⇒ under fixed-priority preemptive RTOS they time-slice or run FIFO when both ready.
Periods and budgets (not priority elevation) provide determinism.

3.2 Rate structure (example; tune per board, document WCET in verify/)

  Entity   Period      Budget (example)   Work                                                               Actor / Queue
  -------  ----------  -----------------  --------------------------------                                   ----------------------------
  IRQ      event/1ms   <= 50 us           process ≤ N TRBs; write wait-free pointer slot; post EVENT_INPUT   posts to INPUT MPSC
  INPUT    1 ms        <= 200 us          read snapshot; edge buttons; snd_evt KEY/BUT (gated MOVE)          ACTOR_INPUT drains its queue
  UI       8.33 ms     <= 6 ms            get_evt ≤ Q; workbench; render BACKBUFFER only                     ACTOR_UI drains its queue
  PRESENT  8.33 ms     <= 1.5 ms or DMA   present frame; must not block; INPUT period                        may share UI queue or own core

3.3 NuttX parallels

  NuttX idea                    B-System mapping
  ----------------------------  ------------------------------------------
  High-rate periodic task       TASK_INPUT @ 1 kHz (or cyclic handler)
  Lower-rate display task       TASK_UI @ ~120 Hz
  Equal priority + RR/FIFO      pri(input) == pri(ui)
  Deferred interrupt work       IRQ only posts semaphore / event flag / MPSC message
  wdog / timer                  system timer or cyclic handler @ 1 ms
  Bounded critical sections     wait-free pointer seqlock or pure MPSC enqueue

4. Data path (deterministic)
----------------------------

  IRQ (bounded)
    xhci_process_events() /* <= N TRBs */
    write pointer snapshot (seqlock / double buffer)
    if key/button pending -> post EVENT_INPUT
    return

  TASK_INPUT (period 1 ms, pri P)
    wait period or EVENT_INPUT
    read snapshot
    integrate / accel (bounded)
    snd_evt for KEY/BUT only (and gated MOVE)
    /* never full paint */

  TASK_UI (period ~8 ms, pri P)
    get_evt (<= Q events)
    workbench_process_event
    if dirty && budget remains -> render backbuffer
    signal PRESENT

  TASK_PRESENT (pri P) or UI tail
    DMA/flip preferred; if CPU blit, budget-capped + IRQs stay enabled

Rule (SMP paper §4): Long work runs only inside the UI/PRESENT actor under an explicit budget.
When the budget is exhausted the actor yields (or simply returns to its tight drain loop) and continues next period.
On Tier 2 the producer side of any inter-actor communication is a pure CMPXCHG8 enqueue (12–25 cycles);
the consumer side is a non-blocking atomic pop. Zero privilege transitions, zero page-table switches,
zero register save/restore for the message path itself.

5. Rejected patterns (RT view)
------------------------------

  Pattern                              RT violation
  -----------------------------------  ------------------------------------
  USB progress only in GUI loop        Input period jitter = paint WCET
  Drain xHCI inside blit scanlines     Present WCET includes USB; analysis harder; architectural coupling
  Unbounded process_events in IRQ      ISR WCET unbounded under flood
  Unbounded EV_MOUSE_MOVE storm        Queue growth non-deterministic
  Heap alloc in IRQ or input period    Non-deterministic latency
  Equal pri but no yield during blit   Peer starvation for a full period
  Raise input permanently above UI     Conflicts with equal-priority policy
  Full mailbox IPC per HID packet      Unnecessary; wrong layer
  Place DP/gpachics behind user-space  Classic NT 3.51 failure mode (btron-smp.tex §4)

6. Implementation phases (RT-ordered)
-------------------------------------

Phase 0 — Measure WCET / jitter - Deliverables
  - Instrument: IRQ entry->exit, input period jitter, max event-ring lag, blit duration (idle and full dirty desktop).
  - async_rt_stats + global menu HUD
  - Short note of measured maxima (screenshot or values) before Phase 1
  - Deliverable: table of observed maxima -> choose T_isr_max, Bi, Bu.
  - Baseline under continuous dirty redraw must show gap_max ≫ Ti; after Phase 1 gap_max ≤ 2 ms.

Phase 1 — Bounded IRQ + periodic INPUT (equal pri with UI) - Deliverables
  - Timer IRQ @ 1 kHz OR xHCI IRQ with deferred INPUT wake.
  - ISR: drain <= N TRBs; update wait-free pointer; post flag; return.
  - TASK_INPUT @ priority P, period 1 ms: keys/buttons -> snd_evt.
  - GUI becomes TASK_UI @ priority P, period ~8 ms.
  - Remove sole dependence on "poll USB only at top of GUI while".
  - Exit: max gap between pointer snapshots <= 2*Ti under continuous paint.

Phase 2 — Bounded queues and policies - Deliverables
  - Event ring: <= N TRBs per IRQ; excess left for next tick.
  - System EVT queue: fixed size; on full drop oldest EV_MOUSE_MOVE; prefer never dropping BUT/KEY.
  - Mouse: no multi-frame software accum as primary path.

Phase 3 — Multi-TRB EP1 (device-side determinism) - Deliverables
  - 2-4 fixed buffers/TRBs in flight per mouse.
  - Eliminates non-deterministic host idle gap after single completion.
  - Files: src/drivers/bcm283x/usb/xhci.c (and UEFI xHCI path).

Phase 4 — Present without starving periods - Deliverables
  - Prefer DMA/page-flip so CPU blit WCET leaves the analysis.
  - If CPU blit remains: only inside UI/PRESENT budget; IRQs enabled; INPUT still meets period.
  - Do NOT require in-blit xhci_process_events as the architecture.

Phase 5 — Optional SMP / Actor pinning
- Pin IRQ+INPUT vs UI+PRESENT on distinct cores when N ≥ 2.
- Document memory ordering for the pointer snapshot (seqlock or atomics).
- On Tier 2 the INPUT and UI planes become (or post into) the N-core / N-queue MPSC topology of core_smp.c.

Phase 0 — Measure WCET / jitter (display on global top menu)
-------------------------------------------------------------

Goal: Prove input batching vs present cost with live numbers on the
Workbench global menu bar (Deskbar / top status strip), so tuning
does not require a serial console.

Instrumentation (collect every INPUT period or once per UI period)
  - irq_us          : last IRQ entry->exit duration (us)
  - irq_us_max      : max irq_us since boot or since reset key
  - input_gap_us    : time since previous pointer snapshot / process_events
  - input_gap_max   : max input_gap_us under load
  - trb_per_irq     : TRBs drained in last IRQ (and max)
  - blit_us         : last full blit or present duration (us)
  - blit_us_max     : max blit_us
  - accum_abs_max   : max |s_accum_dx| + |s_accum_dy| before integrate (baseline; should fall after Phase 1-2)

Display (global top menu / status strip):
  Extend global menu bar status area (right side of top rail, near
  clock / TIP badge) with a compact, fixed-width telemetry string so
  layout does not jitter:

    Expected format (keep under ~40 columns):

      IN 1.2ms  GAP 0.8/14ms  BLIT 1.1ms

Rules:
  - Update label at UI period (Tu), not every HID report.
  - Use fixed-width fields (pad numbers) to avoid menu reflow.
  - Colors optional: green if gap_max <= 2ms; amber <= 5ms; red above.
  - Toggle: menu item or key (e.g. under 道具・文字 or debug build flag ASYNC_TELEMETRY=1) to show/hide and to reset maxima.
  - Debug builds only by default; no allocation in IRQ when formatting — format in TASK_UI from atomic/snapshot counters written by IRQ and INPUT.

Where to hook:
  - Counters: xhci IRQ / timer path and blit_backbuffer_to_fb (or present)
  - Snapshot for UI: wait-free struct async_rt_stats (seqlock or atomics)
  - Draw: global_menu render path (same place as clock), e.g. global_menu.c status strip painter

Pass criteria (Phase 0 complete when)
  - Top menu shows live gap / max gap / blit while moving the mouse and while forcing continuous dirty redraw.
  - Baseline documented: under full desktop redraw, gap_max is clearly larger than Ti (expected today); after Phase 1, gap_max <= 2ms remains visible on the same HUD without serial.

7. Shared state (determinism)
-----------------------------

Pointer snapshot (IRQ -> INPUT/UI):

  struct pointer_slot {
    uint32_t seq;       /* seqlock */
    int16_t  x, y;
    uint8_t  buttons;
    uint8_t  _pad;
  };

  Writer: IRQ (single writer).
  Readers: INPUT and UI (retry on seq change).
  No mutex on common path => no inversion between equal-priority tasks/actors.

EVT queue: existing snd_evt/get_evt with fixed capacity and documented drop policy.
On Tier 2 any cross-core signalling uses the lock-free MPSC primitives of the SMP paper.

8. API sketch
-------------

  void input_plane_on_irq(void);     /* bounded: process_events + snapshot */
  void input_plane_task(void);       /* period Ti: KEY/BUT snd_evt */
  void input_plane_get_pointer(H *x, H *y, uint8_t *buttons);

  typedef void (*xhci_mouse_report_fn)(int16_t dx, int16_t dy, uint8_t buttons);
  void xhci_set_mouse_report_callback(xhci_mouse_report_fn fn);

  void present_request_frame(void);
  int  present_is_busy(void);

ISR rules:
  - No workbench_render, no full blit, no heap.
  - snd_evt from ISR only if queue is IRQ-safe; else defer to TASK_INPUT.

11. Relation to EVENTING.md
---------------------------

- EVENTING.md remains the authoritative description of Workbench dispatch order, window manager, and application event_handler.
- What changes is who calls xhci_process_events and when pointer samples become coordinates:
  under a periodic, budgeted input plane (or actor), not under the paint loop.
- Passive motion stays largely outside snd_evt; discrete interaction remains the EVT stream.
- On Tier 2 the same EVT stream is delivered by the lock-free MPSC queues of the Erlang actor core;
  the graphical DP engine stays in Ring 0 / shared higher-half exactly as required by the NT 4.0 lesson and the SMP paper.
