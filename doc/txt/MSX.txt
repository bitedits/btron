0. Architectural Principles & Philosophy
----------------------------------------

0.1 Core Thesis

The B-MSX emulator (and its embedded core `tronMSX`) provides a deterministic,
cycle-accurate emulation environment for the MSX standard family directly
integrated into the B-System BTRON 3.20 workbench.

Key architectural invariants:
  1. Pure C99 Implementation: Zero external C++ dependencies, zero host GUI
     framework baggage. Adheres strictly to NASA JPL Power-of-10 safety rules.
  2. Zero Post-Boot Dynamic Allocations: Static bounds on all buffers, rings,
     and machine state. No heap churn during emulation frames.
  3. Zero Quality Degradation: Multi-CPU architecture guarantees that support
     for newer or extended models (such as the Hitachi HD64180 or ASCII R800)
     falls through seamlessly to the standard Z80 core, leaving existing MSX,
     MSX2, and MSX2+ timing, cycle counts, and behaviors 100% untouched.
  4. First-Class Real-Body Integration: MSX software packages are represented
     as first-class B-System real-bodies (BMSX records), directly launchable
     from the BTRON Application Menu (A) or file manager.

1.2 Dual-BIOS Architecture (C-BIOS + Nextor vs T-BIOS + T-DOS):
  B-MSX provides two fully decoupled, clean-room BIOS architectures selectable at runtime:
  - C-BIOS Mode (Standard / Default):
    * Loads `cbios_main_*.rom`, `cbios_sub.rom`, `cbios_music.rom`, and `cbios_disk.rom` / `nextor-tc8566af.rom`.
    * Default at application boot. 100% backward compatible with existing configurations.
  - T-BIOS + T-DOS Mode (Clean-Room Native System):
    * Loads `tbios_main_*.rom`, `tbios_sub.rom`, `tbios_music.rom`, and `tdos_disk.rom`.
    * Dedicated top-level `BIOS(B)` menu in the B-MSX Workbench interface:
        (*) C-BIOS + Nextor (標準 / Default)
        ( ) T-BIOS + T-DOS (Clean-Room)
    * T-DOS kernel embeds full Grauw Page-0 RAM environment, MSX-DOS 1 FCB calls ($00–$30),
      MSX-DOS 2 file handles and environment variables ($40–$6F), and EXTBIO $0402 Memory Mapper.

1.3 Firmware Resolution & Fallback Law:
  - C-BIOS images are resolved from explicit configuration, `/SYS/cbios`, or vendor fallback trees.
  - T-BIOS images are resolved from `.build/tbios/` or `/SYS/tbios`.
  - HC-90 / HC-95 models map `cbios_main_msx2_jp.rom` or `tbios_main_msx2_jp.rom`.
  - `machine_has_kanji` is asserted for Japanese MSX2, MSX2+, turbo R, and Hitachi HC-90/HC-95.
  - `machine_has_fdd` is asserted for disk machines, loading `cbios_disk.rom` or `tdos_disk.rom`.


2. Multi-CPU Architecture
-------------------------

The CPU subsystem operates via three coordinated cores sharing the unified `z80` register context:

2.1 Zilog Z80A Core (`z80.c` / `z80.h`):
  - Standard clock: 3.579545 MHz (`MSX_XTAL / 3`).
  - Instruction-cycle boundary model passing ZEXALL tests AV-0.
  - Interrupt handling: IM 0, IM 1 (RST 38H), and IM 2 (VDP vector `(I << 8) | 0xFF`).
  - Edge-triggered NMI (1.34 ms periodic BIOS pulse).
  - Accurate `DI`/`EI` single-instruction delay semantics.

2.2 ASCII R800 Core (`r800.c` / `r800.h`):
  - Turbo R processor executing at 7.159090 MHz bus clock (28.6 MHz CPU clock).
  - Each bus cycle corresponds to 2 CPU cycles (`bus_t = (delta + 1) >> 1`).
  - Intercepts `0xED` prefixed 16-bit multiply instructions:
    * `MULUB A, r` (14 T): Unsigned 8-bit multiply stored in HL (`HL = A * r`).
    * `MULUW HL, rr` (36 T): Unsigned 16-bit multiply stored in DE:HL (`DE:HL = HL * rr`).
  - Non-multiply instructions fall through directly to `z80_step(cpu)`.

2.3 Hitachi HD64180 Core (`hd64180.c` / `hd64180.h`):
  - High-performance CMOS microprocessor utilized in the Hitachi HC-90 and HC-95 workstations.
  - CPU Clock: 6.144000 MHz.
  - Fully backward compatible with Z80 opcodes: non-extended instructions execute via `z80_step`
    with zero overhead, ensuring 100% preservation of standard MSX behavior.
  - Extended `0xED` opcodes implemented:
    * `MLT rr` (17 T): 8-bit unsigned integer multiplication. Flags remain unaffected.
      - `ED 4C`: `MLT BC` -> `BC = B * C`
      - `ED 5C`: `MLT DE` -> `DE = D * E`
      - `ED 6C`: `MLT HL` -> `HL = H * L`
      - `ED 7C`: `MLT SP` -> `SP = SP_H * SP_L`
    * `IN0 r, (m)` (12 T): Reads on-chip I/O port `m` (or external bus if `m` is outside internal base).
      - `ED 00/08/10/18/20/28/38 m`: Destination B, C, D, E, H, L, A.
      - `ED 30 m`: Tests on-chip input without register modification.
      - Flags affected: S (bit 7), Z (result == 0), H=0, P/V (parity), N=0. Carry unchanged.
    * `OUT0 (m), r` (13 T): Outputs register `r` to on-chip I/O port `m`. Flags unaffected.
      - `ED 01/09/11/19/21/29/39 m`: Source B, C, D, E, H, L, A.
    * `TST r` (7 T): Non-destructive logical AND between `A` and register `r`.
      - `ED 04/0C/14/1C/24/2C/3C`: Target B, C, D, E, H, L, A.
      - Flags affected: S, Z, H=1, P/V=parity, N=0, C=0.
    * `TST (HL)` (13 T): `ED 34` -> Non-destructive AND between `A` and `(HL)`. Same flags.
    * `TST imm` (9 T): `ED 64 m` -> Non-destructive AND between `A` and immediate `m`.
    * `TSTIO imm` (12 T): `ED 74 m` -> Non-destructive AND between on-chip port `C` and immediate `m`.
    * `SLP` (8 T): `ED 76` -> Halts CPU in sleep state until an interrupt occurs (`cpu->halted = 1`).
    * Block I/O:
      - `OOTIM` (`ED 83`, 15 T) / `OOTIMR` (`ED 93`, 14-15 T): `OUT0 (C), (HL); HL++; B--`.
      - `OTDM` (`ED 8B`, 15 T) / `OTDMR` (`ED 9B`, 14-15 T): `OUT0 (C), (HL); HL--; B--`.
  - On-Chip Programmable Reload Timers (PRT Channels 0 and 1):
    * Clocked at `phi / 20` (every 20 CPU cycles via `hd64180_advance`).
    * Registers: Timer 0 Counter `0x0C–0x0D`, Reload `0x0E–0x0F`; Timer 1 Counter `0x14–0x15`, Reload `0x16–0x17`.
    * Control Register (`TCR` at `0x10`): Bit 0/1 (`TIE0/1`) enables timer interrupt; Bit 4/5 (`TIF0/1`)
      flags timer underflow and reload.
  - On-Chip Memory Management Unit (MMU):
    * 20-bit physical address space (up to 1 MiB addressable memory).
    * Registers: CBR (`0x38`, Common Base Register), BBR (`0x39`, Bank Base Register), CBAR (`0x3A`, Common/Bank Area Register).
    * Three-area dynamic address translation: Common Area 0 (0..BA-1), Bank Area (BA..CA-1), Common Area 1 (CA..15).
  - On-Chip Direct Memory Access Controller (DMAC Channels 0 and 1):
    * Channel 0: Memory-to-Memory, Memory-to-I/O, I/O-to-Memory transfers.
      - SAR0 (`0x20–0x22`, 20-bit Source Address), DAR0 (`0x23–0x25`, 20-bit Destination Address),
        BCR0 (`0x26–0x27`, 16-bit Byte Count).
    * Channel 1: Memory-to-I/O transfers.
      - MAR1 (`0x28–0x2A`, 20-bit Memory Address), IAR1 (`0x2B–0x2C`, 16-bit I/O Address),
        BCR1 (`0x2E–0x2F`, 16-bit Byte Count).
    * Control & Status: DSTAT (`0x30`, DE0/DE1 enable, DWE0/DWE1 write-enable, DIE0/DIE1 interrupt enable, DME master enable),
      DMODE (`0x31`, source/destination auto-increment/decrement/fixed modes), DCNTL (`0x32`, wait insertion).
  - On-Chip Asynchronous Serial Communication Interface (ASCI Channels 0 and 1):
    * Full-duplex independent serial channels with 16-byte FIFO buffers.
    * Registers: CNTLA0/1 (`0x00/0x01`), CNTLB0/1 (`0x02/0x03`), STAT0/1 (`0x04/0x05`, TDRE, RDRF, overrun flags),
      TDR0/1 (`0x06/0x07`, transmit data), RDR0/1 (`0x08/0x09`, receive data).
  - On-Chip Clock Synchronous Serial I/O (CSIO):
    * Half-duplex synchronous communication interface.
    * Registers: CNTR (`0x0A`, EF end flag, EIE end interrupt enable, RE/TE enable), TRDR (`0x0B`, transmit/receive data).


3. Video Display Processor (VDP) Subsystem
------------------------------------------

B-MSX emulates the Texas Instruments TMS9918A (MSX1) and Yamaha V9938 / V9958 / V9968 (MSX2/2+/Workstations):

3.1 Dual I/O Port Mapping:
  Standard MSX assigns the VDP ports to `0x98–0x9B`. On MSX2 workstations (including the Hitachi
  HC-90/HC-95, Sony HB-G900, and Yamaha AV systems), the video expansion bus mirrors these registers
  onto `0x88–0x8B`. B-MSX decodes both port families identically:

    Primary   Mirror   Function
    -------   ------   ------------------------------------------------------------
    0x98      0x88     VRAM Data Read / Write (auto-incrementing address)
    0x99      0x89     VDP Status Read (S0-S9) / Address & Register Write Setup
    0x9A      0x8A     VDP Palette Data Write (2 successive bytes per palette entry)
    0x9B      0x8B     Indirect Register Write (writes data to register in R#16)

3.2 Display Modes & Acceleration:
  - Screen Modes: SCREEN 0 (Text 40/80), SCREEN 1 (Text 32), SCREEN 2 (Graphics 1),
    SCREEN 3 (Multicolor), SCREEN 4 (Graphics 2), SCREEN 5 (Bitmap 256x212 16-color),
    SCREEN 6 (Bitmap 512x212 4-color), SCREEN 7 (Bitmap 512x212 16-color), SCREEN 8 (Bitmap 256x212 256-color).
  - Hardware Acceleration: V9938 command engine fully modeled (HMMV, LMMV, HMMC, LMMC, HMMM, YMMM, LINE, SRCH).
  - Geo3D Coprocessor: Maps 3D math and hardware polygon rasterization hooks to ports `0x8D, 0x9D, 0x8F, 0x9F`.


4. Slot System & Memory Architecture
------------------------------------

MSX defines a four-slot architecture addressed in 16 KiB pages:
  - Page 0: `0x0000–0x3FFF` (Main BIOS / C-BIOS ROM)
  - Page 1: `0x4000–0x7FFF` (Cartridge ROM Block 0 / Sub-ROM)
  - Page 2: `0x8000–0xBFFF` (Cartridge ROM Block 1 / Main RAM)
  - Page 3: `0xC000–0xFFFF` (Main RAM / Subslot Registers)

4.1 Slot Registers:
  - Primary Slot Select (`PPI Port 0xA8`): Bits 0-1 (Page 0), 2-3 (Page 1), 4-5 (Page 2), 6-7 (Page 3).
  - Secondary Slot Select (`Memory 0xFFFF`): Four subslots per primary slot.
  - Memory Mapper: Standard 512 KiB expandable up to 4 MiB RAM via I/O ports `0xFC–0xFF`.
  - MegaROM Mappers: Full 20-mapper suite covering ASCII8/16 with battery-backed SRAM,
    Konami SCC & SCC+ (SCC-I independent 5th channel), Game Master 2 (SRAM), Irem R-Type,
    Zemina 80-in-1 / 90-in-1, Cross Blaim, Super Lode Runner, Harry Fox, Halnote, Majutsushi,
    NEO8/16, Manbow2, and linear cartridges up to 4 MiB.


5. Sound Chip & MIDI Layer
--------------------------

Multi-chip concurrent synthesis mixed to 44.1 kHz 16-bit signed stereo PCM:
  - AY-3-8910 / YM2149 PSG: 3 square-wave channels + 1 white noise generator at ports `0xA0–0xA3`.
  - Konami SCC / SCC+ (SCC-I): 5 wavetable channels (32-byte cyclic wave memory per channel)
    with RAM write mode and independent 5th channel synthesis at `$B800–$B8AF`.
  - Yamaha YM2413 (OPLL / MSX-MUSIC): 9 FM channels or 6 FM melody + 5 rhythm instruments at `0x7C–0x7D`
    with `"APRLOPLL"` header at `$4018`.
  - Yamaha Y8950 (MSX-AUDIO): 9 FM channels with rhythm and ADPCM synthesis at `0xC0–0xC1`.
  - MSX turbo R PCM: 8-bit DAC/ADC clocked through `t9769c_advance` at port `0xA4–0xA5`
    with `PCMPLY ($0186)` and `PCMREC ($0189)` BIOS integration.
  - MSX-MIDI & turbo R MIDI Interface:
    * Standard MIDI hardware mapped at I/O ports `0xE8–0xEF`.
    * Intel 8251 UART (`0xE8` Data, `0xE9` Status/Control) with TxRDY/RxRDY/TxEMPTY flags and FIFO.
    * Intel 8253 Timer (`0xEC–0xEE` Counter 0..2, `0xEF` Control Word).
    * Timer Counter #2 Interrupt Release / Clear at write to `0xEA`/`0xEB`.
  - Hitachi HC-90 / HC-95 Audio: Standard unipolar PSG mixed cleanly at 60 Hz frame intervals.


6. Verification & Automated Test Harnesses
------------------------------------------

B-MSX includes dedicated automated regression test suites:
  1. `make test-hd64180`: Validates HD64180 instruction execution (`MLT`, `IN0`, `OUT0`, `TST`, `TSTIO`, `SLP`,
     block I/O, PRT reload countdown, MMU 20-bit translation, DMAC block transfers, ASCI FIFO, CSIO, and Z80 backward compatibility).
  2. `make test-tbios`: Comprehensive suite of all 7 T-BIOS clean-room test harnesses:
     - `test_tbios_diff`: Dual-BIOS differential verification and menu switching.
     - `test_tbios_core`: Main ROM reset, CHKRAM, slot dispatch, PPI keyboard, interrupt handling.
     - `test_tbios_video`: V9938/V9958/V9968 display modes, palette engine, Sub-ROM jump table.
     - `test_tbios_audio`: PSG, OPLL ("APRLOPLL"), Y8950, SCC/SCC+, and MSX-MIDI / turbo R MIDI.
     - `test_tbios_cpu`: R800 turbo R CPU mode switching, PCM playback, HD64180 MMU address translation.
     - `test_tbios_megarom`: 20 MegaROM mappers, SRAM persistence, 4 MiB mapper, 100% corpus ROM boot.
     - `test_tbios_disk`: T-DOS Disk ROM, Page-0 RAM environment, FAT12/16 engine, MSX-DOS 1/2 calls, 100% corpus DSK boot.
  3. `make test-msx-boot`: Headless boot test verifying frame execution and VDP ink output.
  4. `make test-msx-audio`: Headless synthesis test validating sample generation and saturation.
  5. `make test-msx-dsk`: Validates floppy disk sector reading and FAT12 media parsing.
  6. `make test-zexall`: Runs the standard ZEXALL instruction exerciser against the Z80 core.
  7. `make test`: Executes all 42+ B-System unit and integration test targets across the entire operating system.
