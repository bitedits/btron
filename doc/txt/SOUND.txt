0. EXECUTIVE OVERVIEW & THE AUDIO-VISUAL SHIM PRINCIPLE
=======================================================================================

In traditional game development, audio and 3D graphics operate as disconnected silos:
a 3D modeler creates a mesh, an animator crafts keyframes, and an audio designer attaches
pre-recorded WAV/OGG audio files to animation event tags.

In the BTRON Lil Cube 64 game architecture, we establish a unified paradigm:

                     THE AUDIO-VISUAL SHIM PRINCIPLE
                     ==============================
  Every fundamental 3D kinematic action of the character maps 1-to-1 to a
  deterministic procedural DSP algorithm called a "Sound Shim". These shims
  require ZERO external sample files (0-byte footprint) and extrapolate into
  rich acoustic instrument palettes that assemble entire multi-track level stages.

              +------------------------------------------+
              | 3D Kinematics (Low-Poly Little Cube 64)  |
              |  - Pulse / Squash (Volumetric Breathing) |
              |  - Waddle / Walk  (Bipedal Phase Roll)   |
              |  - Float / Hover  (Anti-Gravity Drift)   |
              |  - Dance / Spin   (16th Pirouette Steps) |
              |  - Sing / Climax  (Harmonic Radiance)    |
              +------------------------------------------+
                                   |
                      Phase-Locked Direct Resonance
                                   v
              +------------------------------------------+
              | Procedural Sound Shims (DSP Node Graphs) |
              |  - shimPulseSquash / shimPulseBell       |
              |  - shimWaddle (Acoustic Walking Bass)    |
              |  - shimFloat (Rhodes / Modal Harmonies)  |
              |  - shimDance (Star/Coin Arpeggio Runs)   |
              |  - shimDing (Crystalline Ride Chimes)    |
              +------------------------------------------+
                                   |
                     Extrapolated Instrument Banks
                                   v
              +------------------------------------------+
              | Multi-Channel Level Soundtracks (Stages) |
              |  - Level 1: 鐘のキャロル (168 BPM Vivace) |
              |  - Level 2: Green Caterpillar (98 BPM)   |
              |  - Level 3: 朝日のあたる家 (76 BPM 6/8)  |
              |  - Level 4: TRON Init (132 BPM Cyber)    |
              +------------------------------------------+

Key Architectural Advantages:
1. Zero Loading Latency: Instantaneous procedural instantiation at 0 bytes asset size.
2. Perfect Synchronization: Frame-accurate phase alignment between physics and sound.
3. Memory Footprint: Fits entirely within strict embedded RAM budgets (sub-100KB code).
4. Procedural Expressiveness: Dynamic pitch scaling, continuous modulation, and
   environmental filter morphing without sample stretching or artifacting.

2. CHARACTER ANIMATION STATE MACHINE & KINEMATICS
=======================================================================================

The character kinematics engine operates a finite state machine (FSM) running in the
main render loop (60 FPS / 16.66ms tick):

2.1 The 7 Canonical Mascot States:

  1. IDLE (待機呼吸)
     - Kinematics: Gentle sinusoidal breathing.
       y_pos = y_base + sin(t * 2.2) * 0.05
       scale_y = 1.0 + sin(t * 2.2) * 0.03
       scale_xz = 1.0 / sqrt(scale_y)  [Isovolumetric conservation]
     - Sound Shim: Ambient golden chi drone (`shimPulseBell`).

  2. WADDLE / WALK (てくてく歩行)
     - Kinematics: Bipedal walking with alternating footfall lift and lateral body roll.
       walkPhase += delta * walkSpeed
       leftFoot.rotX = sin(walkPhase) * 0.45
       rightFoot.rotX = -sin(walkPhase) * 0.45
       bodyGroup.rotZ = sin(walkPhase) * 0.08
       bodyGroup.posY = abs(sin(walkPhase * 2)) * 0.12
     - Sound Shim: `shimWaddle(time, freq, vol)` triggered at phase zero-crossings
       (alternating Root and Fifth bass notes).

  3. FLOAT (ぷかぷか飛行)
     - Kinematics: Anti-gravity levitation with aerodynamic pitch tilt and buoyant drift.
       posY = y_base + 0.8 + sin(t * 1.8) * 0.25
       rotX = -0.15 + sin(t * 1.8) * 0.05
       rotZ = sin(t * 0.9) * 0.10
       feet.rotX = 0.35 (dangling legs in zero-G)
     - Sound Shim: `shimFloat(time, 'm9', vol)` Rhodes modal rolling chords.

  4. DANCE (氷晶のダンス)
     - Kinematics: Rhythmic pirouette spinning and alternating 16th-note heel taps.
       bodyGroup.rotY += 0.12 (Continuous celebratory spin)
       bodyGroup.posY = abs(sin(t * 8.0)) * 0.28 (Energetic bounce)
       hands.rotZ = sin(t * 8.0) * 0.65 (Celebratory arm waving)
     - Sound Shim: `shimDance(time, scale, vol)` rapid 16th-note star arpeggios.

  5. SQUASH / PULSE (神聖波動)
     - Kinematics: Volumetric compression followed by explosive spring rebound.
       Phase 0 (0-80ms): scale_y = 0.60, scale_xz = 1.30 (Pre-pulse anticipation)
       Phase 1 (80-200ms): scale_y = 1.45, scale_xz = 0.82 (High holy elongation)
       Phase 2 (200-450ms): Damped harmonic oscillation back to (1, 1, 1).
     - Sound Shim: `shimPulseSquash(time, pitch, vol)` dual-phase PWM square wave pulse.

  6. JUMP & LANDING (跳躍と着地)
     - Kinematics: Ballistic parabola trajectory with landing squash absorption.
       On Jump: Anticipation squash -> Apex float -> Fast fall -> Ground impact squash.
     - Sound Shim: Jump whoosh -> `shimPianoHammer(time)` + `shimKick(time)` on impact.

  7. SING / CLIMAX (天球の熱唱)
     - Kinematics: Head tilts upward (+25 deg), torso expands, halo glow intensifies.
     - Sound Shim: `shimPulseSquash` singing lead + `shimSaxFlute` high counterpoint.

3. SOUND SHIMS: DEFINITION, PHYSICS & PROCEDURAL DSP ARCHITECTURE
=======================================================================================

3.1 Definition of a "Sound Shim"
A Sound Shim is a self-contained, stateless procedural audio synthesis function written
in JavaScript using the W3C Web Audio API (or pure C/Assembly in native BTRON kernels).
Unlike static audio playback (`AudioBufferSourceNode.buffer = loadedWav`), a Sound Shim
creates and configures active DSP nodes on the fly at exact timestamps ($t = \text{currentTime} + \Delta$).

3.2 Mathematical Formulation of a Sound Shim
A shim $S(t_0, \mathbf{p})$ takes trigger time $t_0$ and parameter vector $\mathbf{p} = (f, v, d, \dots)$
and constructs an acoustic signal $y(t)$:

  y(t) = \sum_{k=1}^{K} A_k(t - t_0) \cdot W_k(2\pi f_k (t - t_0) + \phi_k) * H_k(t)

where:
- $W_k$: Oscillator waveform (sine, triangle, saw, pulse)
- $A_k$: Non-linear ADSR gain envelope with exponential decay:
         $A(t) = V_{\text{peak}} \cdot e^{-(t - t_{\text{attack}}) / \tau}$
- $H_k$: Biquad filter impulse response (formant cavity, body resonance)
- $*$ denotes time-domain convolution (filtering)

3.3 Memory Lifecycle & Automatic Node Disposal
Every node created inside a shim registers into a track garbage tracking array:
`registerTrackOsc(osc)`
When tracks switch or stop, `stopAllTracks()` invokes:
1. `osc.stop(0)` on all active oscillators.
2. `osc.disconnect()` to sever graph connections.
3. Clears reference arrays, permitting browser V8/JSC GC to recycle node memory.
This guarantees zero memory leaks across hours of gameplay.

        │
        ▼
  [Master Compressor / Soft Clipper]
        │
        ▼
  [AudioContext.destination] (Physical DAC / Hardware Speakers)

5.2 WaveShaper Non-Linear Saturation Primitive
To achieve punchy analog warmth without harsh digital clipping:
```javascript
function getDistortionCurve(amount = 25) {
    const k = amount;
    const n_samples = 44100;
    const curve = new Float32Array(n_samples);
    const deg = Math.PI / 180;
    for (let i = 0; i < n_samples; ++i) {
        const x = (i * 2) / n_samples - 1;
        curve[i] = ((3 + k) * x * 20 * deg) / (Math.PI + k * Math.abs(x));
    }
    return curve;
}
```

7. PROGRAMS (PATCHES, TRACKER PRESETS & SOUNDFONT SCHEMAS)
=======================================================================================

In the BTRON sound architecture, a "Program" is an immutable parameter vector defining
a virtual instrument. Instead of massive multi-megabyte soundbanks, programs are defined
in concise declarative schemas:

```json
{
  "programId": "PROG_CHIPTUNE_BELL_LEAD",
  "baseShim": "shimDing",
  "octaveOffset": 0,
  "defaultVelocity": 0.24,
  "decaySeconds": 0.70,
  "filterType": "bandpass",
  "filterQ": 4.5,
  "harmonicDoubling": [
    { "pitchRatio": 2.0, "volumeRatio": 0.65, "delayMs": 2.0 }
  ]
}
```

This allows game levels to load custom instrument libraries dynamically with zero
network overhead or asset streaming delay.

8. TRACKS AS SIGNAL LINES, CHANNELS, MICROPHONES & SPATIAL SOUND SOURCES
=======================================================================================

8.1 Spatial Audio Architecture
In Lil Cube 64, sound sources exist in 3D coordinate space $(x, y, z)$:
- Listener: Located at the player camera position $(0, 0.08, 9.2)$ looking at $(0, 0, 0)$.
- Stereo Panning Law:
  We implement constant-power panning ($3\text{ dB}$ compromise):
  $$\text{Gain}_L = \cos\left(\frac{\pi}{4} \cdot (p + 1)\right), \quad
    \text{Gain}_R = \sin\left(\frac{\pi}{4} \cdot (p + 1)\right)$$
  where $p \in [-1.0, +1.0]$ is the horizontal pan position.

8.2 Distance Attenuation
Sound pressure decreases with inverse distance:
  $$\text{Gain}_{\text{dist}} = \frac{d_{\text{ref}}}{d_{\text{ref}} + \max(0, d - d_{\text{ref}})}$$
At large distances, a 1-pole lowpass filter cuts high frequencies above 2kHz to simulate
atmospheric air absorption.

9. TRACKS AS COMPOSITIONS: THE TRACKER GRID & MATHEMATICAL TIMING
=======================================================================================

9.1 Tracker Timing Equations
Every track composition is governed by strict beat and subdivision formulas:

  T_{\text{beat}} = \frac{60}{\text{BPM}} \text{ seconds}
  T_{\text{bar}}  = T_{\text{beat}} \times \text{beatsPerMeasure}
  T_{\text{8th}}  = \frac{T_{\text{beat}}}{2}
  T_{\text{16th}} = \frac{T_{\text{beat}}}{4}

9.2 Tracker Channel Matrix
Each composition is arranged across 6 to 8 parallel procedural voice channels:
- Channel 1: Bass / Sub Foundation (`shimWaddle`, `shimPedalBass`, `shimIndustrialBass`)
- Channel 2: Drum / Rhythm Section (`shimKick`, `shimSnare`, `shimHiHat`, `shimDing`)
- Channel 3: Chordal Harmony / Pad (`shimFloat`, `shimPulseBell`, Rhodes)
- Channel 4: Primary Lead Melody (`shimPulseSquash`, `shimGrandPiano`, `shimViolin`)
- Channel 5: Counterpoint / Woodwind (`shimSaxFlute`, `shimGuitar`)
- Channel 6: Star Arpeggios / FX (`shimDance`, `shimSwarmatron`)
- Channel 7: High Sparkle / Crystalline Chimes (`shimDing` high octave)

10. CHARACTER MOVEMENT SYNCHRONIZATION WITH SOUND SHIMS (PHASE-LOCKING)
=======================================================================================

10.1 Phase-Locking Architecture
The 3D render loop and the Web Audio scheduler share the high-resolution audio clock
`AudioContext.currentTime`.
When an animation plays:

1. Bipedal Walk (Waddle):
   - At `walkPhase = 0` (Left foot impact): Triggers `shimWaddle(time, rootF, vol)`.
   - At `walkPhase = \pi` (Right foot impact): Triggers `shimWaddle(time, fifthF, vol)`.
   The character literally walks on the bassline of the music!

2. Floating (Float):
   - When reaching apex height $y_{\text{max}}$: Triggers `shimFloat(time, chord)` rolling chord.
   - Particle bubbles emit in Three.js in exact synchrony with the Rhodes tines.

3. Dancing (Dance):
   - Every 90-degree pirouette rotation triggers a 16th-note `shimDance` arpeggio bead.
   - The crystalline star sparkles emitting from Lil Cube match each audio ping.

4. Volumetric Pulse (Squash):
   - On impact compression ($y = 0.60$): Physical felt strike `shimPianoHammer`.
   - On expansion release ($y = 1.45$): Radiant shockwave `shimPulseSquash` burst.

12. ADAPTIVE AUDIO & INTERACTIVE GAMEPLAY MECHANICS
=======================================================================================

12.1 Interactive Quantization Grid
When the player presses Space (Holy Pulse), clicks, or touches Lil Cube 64:
- The input event is quantized to the nearest upcoming 16th or 8th note boundary:
  $$t_{\text{trigger}} = t_{\text{bar\_start}} + \lceil \frac{t_{\text{input}} - t_{\text{bar\_start}}}{T_{\text{16th}}} \rceil \times T_{\text{16th}}$$
This ensures player interactions NEVER clash with the background music; player actions
sound like intentional, virtuoso musical improvisations!

12.2 Dynamic Stem Mixing
- Player at full health: Melody, drums, bass, and harmony play at 100% volume.
- Player taking damage: Highpass filter closes down to 800Hz, heartbeat kick drum enters.
- Player collecting Star/Invincible: `shimDance` arpeggio channel un-mutes at $+3\text{ dB}$.
