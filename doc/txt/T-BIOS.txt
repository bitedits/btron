# T-BIOS & T-DOS — Definitive Clean-Room Implementation Plan

Goal: a BSD-attributed, independently written MSX / MSX2 / MSX2+ / MSX turbo R / Hitachi HC-90/95 system ROM set (**T-BIOS**) paired with a clean-room disk operating system (**T-DOS**) for B-MSX, built in-tree with the **SDCC + pasmo** stack:

- **Default is C-BIOS + Nextor.** Existing C-BIOS machines (including C-BIOS FDD with Nextor) remain the default and keep 100 % of their current behaviour.
- **T-BIOS + T-DOS is selectable from its own `BIOS(B)` menu** in the B-MSX application menu bar (§4.5).
- **100 % `./assets/msx` corpus compatibility:** every `.rom` and `.dsk` image in `./assets/msx` (plus the Aurel Vault ROMs) runs 100 % on T-BIOS + T-DOS (§2).
- **≥ 80 % well-known MSX-DOS game & application compatibility:** T-DOS implements the DOS 1 FCB and DOS 2 file-handle, environment, and memory-mapper calls used by ≥ 80 % of known MSX-DOS games without needing MSX-DOS or Nextor sources (§2.2, §4.4).
- **Full hardware support:** Z80, R800 (turbo R), and HD64180 (HC-90/95) CPUs, full MegaROM mapper suite, and all video (V9938/V9958/V9968) and audio (PSG, YM2413 OPLL, Y8950 MSX-AUDIO, SCC/SCC+, turbo R PCM, MIDI) hardware (§4.2, §4.3).
- **Self-contained in `./btron` (no submodules):** toolchain helpers (`ihx2rom.c`, `crt0_btron.s`, `tbios_hw.h`, `tbios_hw.c`) are imported directly into `src/emulators/msx/tbios/` (§4.1).

## 1. Clean-room protocol

**Allowed inputs**

1. **C-BIOS source (BSD licence):** structure, entry offsets, system variable addresses, and algorithms in `third_party/cbios-nextor_FDD-and-turboR/cbios/src/*.asm` may be consulted and followed, keeping the BSD copyright notice.
2. **Public web specifications and datasheets:**
   - Grauw's MSX Assembly Page:
     - MSX-DOS 2 Environment: https://map.grauw.nl/resources/dos2_environment.php
     - MSX-DOS 2 Function Calls: https://map.grauw.nl/resources/dos2_functioncalls.php
     - MSX BIOS / Sub-ROM / System Variables / VDP / Sound resources on `map.grauw.nl` and MSX Resource Center (`msx.org/wiki`)
   - MSX Red Book, MSX2 Technical Handbook, MSX-Datapack, MSX turbo R Technical Handbooks
   - FAT12/FAT16 on-disk format specifications and standard MSX 360K/720K floppy geometry tables
   - Hardware datasheets: TC8566AF, WD2793, V9938, V9958, V9968, AY-3-8910/YM2149, YM2413 (OPLL), Y8950 (MSX-AUDIO), Konami SCC/SCC+, S1985, S1990, T9769B/C, R800, Hitachi HD64180
3. **Black-box observation** of the ROMs and DSKs in `./assets/msx` and our own emulator traces.

**Forbidden inputs for T-BIOS / T-DOS**

- Nextor source (`nextor/source/**`, `driver/*.mac`), because Nextor is a fork of MSX-DOS carrying a no-derivatives restriction. (Nextor binaries remain untouched in the repo solely for the C-BIOS FDD default mode.)
- Disassemblies of proprietary Microsoft / ASCII / Panasonic ROMs or `MSXDOS.SYS` / `MSXDOS2.SYS`.

**Audit trail**

- Every routine in T-BIOS and T-DOS cites its specification tag in `doc/txt/TBIOS.txt` (`[CB:file:label]`, `[GRAUW:dos2_functioncalls#fn]`, `[SPEC:name §n]`) and is recorded in `src/emulators/msx/tbios/PROVENANCE.md`.

### 4.1 Toolchain: Self-Contained SDCC + pasmo in `./btron`

All toolchain code from `../msx.btron.pro` has been imported directly into `./btron` (no git submodules):

    entry_sub.asm      (pasmo: fixed sub-ROM jump table $0000-$01FF)
    entry_disk.asm     (pasmo: fixed disk-ROM header $4000-$402F & BDOS/page-0 stubs)
    entry_music.asm    (pasmo: APRLOPLL header & OPLL jump table)
  c/
    tbios_hw.c         (imported SDCC __naked port I/O & banking primitives)
    init.c slot.c kbd.c joy.c video.c vdp_cmd.c psg.c opll_bios.c rtc.c
    turbor.c hd64180_bios.c
    tdos/
      disk_bios.c fdc_tc8566af.c fat12.c bdos_fcb.c bdos_handle.c
      dos2_env.c dos2_mapper.c tcommand.c

- **Build tools:** `sdcc` and `sdasz80` (`/opt/homebrew/bin/sdcc`), `pasmo` built in-tree from `third_party/pasmo` into `.build/pasmo`, and `.build/ihx2rom` compiled from `src/emulators/msx/tbios/sdcc/ihx2rom.c`.
- **ABI glue:** Fixed entry points in `asm/*.asm` save caller registers, invoke SDCC C routines compiled with `--opt-code-size` / `--opt-code-speed`, and restore MSX BIOS output registers (`AF`, `BC`, `DE`, `HL`, `IX`, `IY`). Time-critical inner loops (`RDSLT`, `WRSLT`, `LDIRVM`, `H.KEYI`) stay in pure Z80 assembly.

### 4.4 T-DOS Architecture (Paired with T-BIOS)

- **Clean Separation:**
  - **C-BIOS mode (Default):** loads `cbios_main_*.rom`, `cbios_sub.rom`, `cbios_music.rom`, and `cbios_disk.rom` / `nextor-tc8566af.rom` exactly as today.
  - **T-BIOS mode:** loads `tbios_main_*.rom`, `tbios_sub.rom`, `tbios_music.rom`, and `tdos_disk.rom` (containing the T-BIOS Disk ROM + T-DOS kernel + `TCOMMAND` shell).
- **T-DOS Components in `tdos_disk.rom`:**
  1. **Disk BIOS (`$4010–$401F`):** `DSKIO`, `DSKCHG`, `GETDPB`, `CHOICE`, `DSKFMT`, `MTOFF` supporting both the emulator's direct sector window and TC8566AF/WD2793 FDC registers, with full multi-sector page-boundary splitting (corner case K3).
  2. **Page-0 Environment (`dos2_environment.php`):** maps Mapper RAM into Page 0, installs `$0000` warm boot, `$0005` BDOS entry, `$0006` TPA top address, inter-slot call trampolines (`RDSLT`, `WRSLT`, `CALSLT`, `ENASLT`, `CALLF`), `$0038` IRQ forwarder, default FCBs at `$005C`/`$006C`, and `$0080` DTA.
  3. **FAT12 / FAT16 File System Engine:** cluster chain traversal and allocation, subdirectory traversal, 8.3 and wildcard matching, BPB-to-DPB computation for 360K / 720K / 1.44M images.
  4. **BDOS Kernel:**
     - DOS 1 FCB & console calls `$00–$30`.
     - DOS 2 file-handle, directory, path-parsing, environment-string (`_GENV`, `_SENV`, `_FENV`), error (`_DEFAB`, `_DEFER`, `_ERROR`, `_EXPLAIN`), and version (`_DOSVER $6F`) calls (`dos2_functioncalls.php`).
     - DOS 2 Extended BIOS (`EXTBIO $FFCA`, `DE=$0402`) Memory Mapper segment table (`ALL_SEG`, `FRE_SEG`, `RD_SEG`, `WR_SEG`, `CAL_SEG`, `PUT_PH`, `GET_PH`).
  5. **Boot & Launcher (`TCOMMAND`):** executes standard MSX boot sectors, runs `AUTOEXEC.BAT` or boots directly into `.COM` / `BSAVE` (`$FE`) programs on disk images, and provides an interactive `A>` command prompt (`DIR`, `TYPE`, `CLS`, `VER`, `MEM`, `CD`, `COPY`, `DEL`, `REN`, `BASIC`).

### 4.5 B-MSX App Menu: Dedicated Top-Level `BIOS(B)` Menu

In [src/emulators/msx/msx_app.c](file:///Users/tonpa/depot/bitedits/btron/src/emulators/msx/msx_app.c) (`msx_init_menu_bar()`):

## 6. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| 32 KiB Main ROM / 16 KiB Sub-ROM / 16 KiB Disk ROM size limits with SDCC code | Compile bulk C modules with `--opt-code-size`, keep jump tables and inner loops in compact `pasmo` assembly, and place T-DOS extended modules in banked 16 KiB Disk ROM pages |
| Page-0 RAM vs BIOS slot mapping during MSX-DOS execution | Follow Grauw's `dos2_environment.php` layout strictly: Page-0 RAM holds inter-slot trampolines at `$000C/$0014/$001C/$0024/$0030` and `$0038` that switch Main BIOS in and out safely |
| Disk images in `./assets/msx` mix boot-sector demos, `.COM` files, and Disk BASIC `BSAVE` (`$FE`) files | T-DOS boot sequence checks for custom boot sector code first, then scans for `AUTOEXEC.BAT` / `.COM` / `BSAVE` `$FE` binaries so all three disk types launch seamlessly |
| Keeping C-BIOS + Nextor 100 % untouched while adding T-BIOS + T-DOS | `bios_mode` defaults to `BMSX_BIOS_CBIOS`; C-BIOS ROMs and Nextor remain intact and isolated from T-BIOS/T-DOS |
