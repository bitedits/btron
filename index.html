B-System VirtIO Architecture

The High-Assurance Paravirtualized Workstation & Real-Time Hypervisor System Plane for Academic Research and Computer Science Curricula

B-System VirtIO is a formal cleanroom implementation of the Japanese BTRON3 Specification 3.20 engineered as a native, lightweight VirtIO 1.4 System Plane. Designed specifically for university research in operating systems, paravirtualized I/O, and real-time computing, B-System liberates TRON workstation technology from vintage proprietary silicon, executing deterministically on modern hypervisors (KVM, QEMU, bhyve, macOS Hypervisor.framework) and microkernel capability architectures (seL4).

By decoupling μITRON real-time scheduling, authentic Sakamura Cho-Kanji windowing, and the Real Object / Virtual Object (実身／仮身) hypermedia filing system into standardized Split Virtqueues, B-System delivers microsecond latency, zero post-boot dynamic memory allocation (NASA JPL Rule 3), and verifiable fault isolation.

1. OASIS VirtIO 1.4 Specification & Memory Ring Architecture PARAVIRTUALIZED I/O

VirtIO paravirtualization eliminates the prohibitive latency of full peripheral hardware emulation (such as IDE, Cirrus VGA, or Realtek NIC register traps). B-System interfaces directly with modern hypervisors via memory-mapped I/O (MMIO) and PCI BAR transports using standard Split Virtqueues.

MMIO Register Offset Value / Invariant Architectural Function in B-System
MagicValue 0x000 0x74726976 ("virt") Hardware identification trap confirming valid VirtIO bus interface.
Version 0x004 0x00000002 Enforces strict VirtIO v1.4 Modern Standard; prevents legacy v0.95 fallback bugs.
DeviceID 0x008 1, 2, 3, 16, 18 Dispatches to Net (1), Block (2), Console (3), GPU (16), or Input/Tablet (18) subsystems.
QueueNumMax 0x034 Power-of-two (e.g. 256) Upper descriptor capacity negotiated between guest driver and host hypervisor.
QueueNotify 0x050 Queue Index (0..N) Host doorbell register triggering paravirtualized hypercall without I/O trapping delay.
Status 0x070 ACK | DRV | OK Driver state machine progression (Acknowledge → Driver → FeaturesOK → DriverOK).

C99 Split Virtqueue Ring Topology (include/device/virtio.h)

Communication occurs via three shared ring buffers allocated in contiguous physical RAM. Hardware volatile barriers (_W, _UW) guarantee zero-copy cache coherency across CPU clusters without race conditions: 

/* 1. Descriptor Table: Points to physical buffer segments */
struct vio_vring_desc {
    uint64_t addr;   /* Physical guest address in RAM */
    uint32_t len;    /* Segment length in bytes */
    uint16_t flags;  /* VIO_VRING_DESC_F_NEXT | F_WRITE | F_INDIRECT */
    uint16_t next;   /* Index of chained buffer in descriptor pool */
};

/* 2. Available Ring: Written by Guest, read by Hypervisor Host */
struct vio_vring_avail {
    uint16_t flags;  /* VRING_AVAIL_F_NO_INTERRUPT suppression flag */
    uint16_t idx;    /* Monotonically increasing submission counter */
    uint16_t ring[]; /* Array of descriptor heads submitted for host processing */
};

/* 3. Used Ring: Written by Hypervisor Host, retired by Guest */
struct vio_vring_used_elem {
    uint32_t id;     /* Descriptor chain head completed */
    uint32_t len;    /* Total bytes written/read by hardware device */
};

struct vio_vring_used {
    uint16_t flags;
    uint16_t idx;    /* Monotonically increasing completion counter */
    struct vio_vring_used_elem ring[];
};

2. The Five Native VirtIO Subsystems in B-System DEVICE ARCHITECTURE

B-System provides a complete, cleanroom C99 driver suite for the five essential workstation virtualization devices defined in the OASIS specification:

VirtIO-GPU (Device 16)

2D SCANOUT & SDL2

Routes BTRON Display Primitives (DP vector rasterizer, pattern fills, font bitmaps) through 2D resource create (0x0101), transfer-to-host (0x0105), and resource flush (0x0104) control packets. On hosted targets, pipes directly into an accelerated SDL2 streaming texture (SDL_PIXELFORMAT_ARGB8888) achieving 60–120 FPS display updates with zero flicker. 

struct virtio_gpu_resource_create_2d cmd = {
    .hdr.type = VIRTIO_GPU_CMD_RESOURCE_CREATE_2d,
    .resource_id = 1,
    .format = VIRTIO_GPU_FORMAT_B8G8R8A8_UNORM,
    .width = 1024, .height = 768
};
virtio_gpu_send_cmd(&cmd, sizeof(cmd));

VirtIO-Input / Tablet (Device 18)

16-BIT ABSOLUTE POINTER

Eliminates mouse drift and relative-pointer capture issues by implementing the VirtIO Tablet protocol. Coordinates are transmitted as normalized 16-bit absolute values (EV_ABS: ABS_X, ABS_Y, 0..32767). The BTRON event manager translates packets into authentic Sakamura cursor events with sub-millisecond click dispatch. 

struct virtio_input_event {
    uint16_t type;  /* EV_SYN, EV_KEY, EV_ABS */
    uint16_t code;  /* ABS_X, ABS_Y, BTN_LEFT */
    uint32_t value; /* Absolute cursor coordinate */
};

VirtIO-Console (Device 3)

PL011 SERIAL UART LINK

Provides unbuffered multi-port character I/O streams directly connecting the gterm terminal emulator and kernel debugger to the host terminal. Operates in bidirectional interrupt-driven mode with fallback to standard PL011 115200 8N1 serial registers on bare-metal ARM systems. 

void virtio_console_putc(char c) {
    vio_queue_push_tx_buffer(&g_cons_vq, &c, 1);
    virtio_notify(VIRTIO_MMIO_CONSOLE, 0);
}

VirtIO-Block (Device 2)

HFDS CABINET STORAGE

Asynchronous sector-level transfer (512B / 4096B) powering the cleanroom BTRON Hierarchical File/Data Set (HFDS). Manages persistent disk cabinets, Real Body record graphs, and Virtual Body link nodes with bounded static block buffers and zero runtime heap growth. 

struct virtio_blk_req {
    uint32_t type;     /* VIRTIO_BLK_T_IN / OUT */
    uint32_t reserved;
    uint64_t sector;   /* 64-bit sector LBA index */
};

4. University Operating Systems Research & Lab Curriculum ACADEMIC SYLLABUS

Traditional university OS courses frequently encounter a dilemma: educational microkernels (such as xv6) lack modern graphical user interfaces, while monolithic production kernels (Linux) exceed 30 million lines of code, making complete conceptual comprehension impossible within a semester.

B-System VirtIO resolves this dilemma. In approximately 25,000 lines of rigorous C99, it provides an end-to-end operational operating system spanning preemptive real-time task scheduling, paravirtualized VirtIO drivers, multilingual font rasterization, an authentic window compositor, and an interactive CUA desktop:

LAB MODULE 1 Real-Time Schedulers

Deterministic Microkernels (μITRON vs Linux CFS)

Students study deterministic priority preemption, priority ceiling protocols (avoiding Mars Pathfinder priority inversion), and bounded task context switching under strict Worst-Case Execution Time (WCET) bounds.

LAB MODULE 2 Virtualization & I/O

Writing a VirtIO Driver from Scratch

Hands-on laboratory where students implement a VirtIO Split Virtqueue descriptor ring, allocate memory-mapped descriptors, and handle asynchronous interrupts without any third-party proprietary frameworks.

LAB MODULE 3 Formal Assurance

NASA JPL Rule 3 & Zero Dynamic Memory

Enforces zero post-boot heap allocation (malloc禁止), static allocation bounds, volatile hardware barriers, and automated verification suites verifying memory leak immunity.

LAB MODULE 4 Hypermedia Architecture

Real Object / Virtual Object Hyper-Data Model

Contrasts the Unix "everything is a linear byte stream" paradigm with Sakamura's relational hypermedia model, investigating polymorphic TAD document streams and decentralized object link graphs.
