B-System · BTRON 3.20 · Media

つくる人の、OS。

音をとりに、紙を組み、立体をつくり、映像を切る。
そのための四つのアプリケーションと、ゲームのための七つの席。
どちらも、標準 C99 でクリーンルームに書き直した一つの BTRON3 の上で動いています。

Two families, one machine. The authoring side of B-System is a digital audio workstation, a desktop publishing system, a 3D system and a non-linear editor. The playing side is a launcher, a game SDK and five machine environments. Every plate below says plainly whether the product ships today, runs on real console silicon, or is only announced.

01 / Authoring

第一部：創作アプリケーション

DAW · DPS · 3DS · NLE

B-System は創作を四つの専門分野として名前づけます。DAW（Digital Audio Workstation）、DPS（Desktop Publishing System）、3DS（3D System）、NLE（Non-Linear Editor）。四つはそれぞれ機械の別の場所を突きます。音は合成とデバイス遅延、組版は用紙の幾何、立体はシーングラフとフレームバッファ、映像は時間とファイル交換です。だから四つを一つの「スイート」にまとめず、それぞれに窓口とマニュアルを与えました。そして出荷済みの二題と、宣言だけの二題を同じ顔で並べず、札を分けて掲げます。

Four disciplines are named instead of one suite, because each one stresses a different contract inside the kernel. Two of them are shipping products with a complete specification page; two are announced, and their cards say so rather than borrowing the confidence of the shipped ones. The distinction is kept visible on purpose: a landing page that cannot tell a build from a plan is not documentation.

01 — DAW / Digital Audio Workstation

管弦楽 (Orchestra) 公開中

ステージのための DAW。使い手を Rock（生バンド）、Classic（声と古典楽器）、Orchestra（フィルハーモニー配置）の三つに固定し、三十二のプログラムをすべて手書きの合成手続きで鳴らします。 SoundFont もサンプルライブラリも使いません。窓は八つ、マニュアルは第十二章です。

  • 二つのサンプルレート48000 と 44100、既定は 48000 Hz
  • ホスト周期 / 量子1024 フレーム、合成量子 Q = 32
  • セッションファイル73,408 バイト固定長。長さがずれたファイルは読まない
  • 遅延の決まり方窓の枚数ではなく、デバイス側の待ち行列の長さ

Orchestra is documented as a manual rather than a feature list: twelve chapters, each one resting on the previous, with the latency figure measured from the audio queue rather than asserted.

02 — DPS / Desktop Publishing System

電子帳票 (Clarity) 公開中

DTP 出版組版環境。和式の伝統判型十四種と、チベット横長ペーチャ経典の組版仕様を、同じエンジン上の二つの紙として扱います。画面の像素ではなく頁の幾何が正しさの単位になる分野で、原稿リンクから印刷所入稿用 PDF までを一手順で通します。

  • 和式伝統判型 14 種四六判の縦書き段組まで仕様として持つ
  • チベット Pecha 組版560 × 110 mm の横長、朱黒二重枠と左余白表題
  • 学術 PostScript 論文数式混植と査読注釈の自動連動
  • 出力木版風 PDF / EPS、四六判・袋綴じ PDF

Publishing is the discipline where geometry is the deliverable: paper formats, not pixel buffers, are what a correctness claim is made about.

03 — 3DS / 3D System

スタジオ (Studio) 準備中

立体をつくる 3D システム。まだお届けしていません。この札に載っているのは宣言だけです。ただしかに床は動いています。B-GL は TinyGL のソフトウェアラスタライザと VirtIO-GPU（virgl）の二つを本番バックエンドとして持ち、ローポリのシーングラフは Lil Cu 64 と MSX の Geo3D が毎日すでに走らせています。

  • 本番バックエンド 2：TinyGL、VirtIO-GPU (virgl)
  • ハードウェアバックエンド 4 は別枠で宣言済み
  • 既存の実装例：デモシーン、MSX Geo3D
  • アプリの窓はまだない — 図面は基盤側

Studio is announced, not shipped. What exists is the layer it will sit on — B-GL, whose two production backends are already exercised every day by the demoscene and by MSX Geo3D titles.

04 — NLE / Non-Linear Editor

カット (Cut) 準備中

映像を切る非線形エディタ。こちらも届け前です。消費する側の図面はすでに書かれています。 B-Video は表示経路とフレームバッファと再生契約を、B-Media は抽象パイプラインと平面ごとの予算を定めます。編集の UI は、その図面の上にはまだ載っていません。

  • 床の仕様：B-Video（表示経路・バッファ・再生契約）
  • 床の仕様：B-Media（抽象パイプラインと平面予算）
  • 音の席は Orchestra が先に埋めている
  • このページのどの画像もカットの画面ではない

Cut is announced, not shipped. The display path and the pipeline contract it will consume are specified documents today; the editing interface is not.

02 / Playing

第二部：クロスメディアバーとゲームの機

XMB · B-Game SDK · MSX · Genesis · Amiga · Iris · Ares

遊び側は七つの席です。起動のバー（XMB）、ゲームをつくる SDK、そして五つの機械 — MSX、メガドライブ、アミーガ、Iris（PS2）、Ares（N64）。この中でいちばん出来ているのは MSX です。CPU、VDP、音源、スロット、キーボード、ジオメトリ演算を別個のコアとして書き、ウィンドウマネージャに組み込み、カートリッジを窓の中の実身として読みます。Iris はエミュレータではなく、B-System が PlayStation 2 の実機そのものに起動する席です。メガドライブとアミーガと Ares は、席だけを置いています。

One launcher, one SDK, five machine environments. One machine emulates today, one is the operating system booting on real console silicon, and three are placeholders with a directory and a name. A launcher that pretends to boot a cartridge nobody has written is worse than a launcher with fewer tiles, so the tiles are labelled.

05 — Launcher

クロスメディアバー (XMB) 公開中

水平のカテゴリ軸と垂直のアイテム軸で行き来する、二軸クロスの統合メディアランチャーです。背景ではリアルタイムの正弦波シェーダーがうねり、実身／仮身のハイパーメディア空間を大画面・ゲームパッド・キーボードで速く閲覧し、速く実行します。

  • 二軸ナビ水平カテゴリ × 垂直アイテム
  • 実装C99 / OpenGL ネイティブ
  • ゼロヒープ事前ベイクのテクスチャアトラスで 60FPS

The XMB is the desk seen from ten feet away: the same document model as the editor, reached with a pad instead of a mouse.

06 — B-Game SDK / B-Sound DSP

リル・キューブ 64 (SDK) 公開中

ゲームをつくるための SDK と、その上で回っているデモシーンです。ローポリの 3D 幾何とシーングラフ、運動学の状態機械、二十三種のプロシージャル音源パレットと B-Sound の DSP が、同じ窓の中で時間を共有しています。創作側と遊び側が出会うのはここです。

  • 音色の使い方23 のシム音源を呼ぶ
  • 幾何ローポリ + シーングラフの階層
  • 律音律・MIDI 周波数・プログラム表
  • 振る舞い空間音響・トラッカー調時・適応型機構

The SDK is where the two families meet: the hand-written synthesis procedures that Orchestra budgets for the stage are the same palette a game calls.

07 — Machine / MSX1 … MSX2

ゲームシステム (MSX) 公開中

カートリッジ実行環境。CPU、VDP、音源、スロット、キーボード、ジオメトリ演算を別個の C コアとして実装し、B-System のウィンドウマネージャに組み込みました。32 KiB のフラット ROM から 4 MiB の MegaROM、Geo3D を内蔵するタイトルまで、同じ窓から起動します。

  • 計算z80.c、r800.c、geo3d.c
  • 描画v9938.c、vdp.c
  • 音源psg.c、scc.c、y8950.c、opll.c、t9769b.c
  • 周辺slots.c、s1985.c、ppi.c、kbd.c、bios.c
  • 検証zexall.c が Z80 命令群を機械に検査させる

MSX is the deepest emulator in the tree precisely because it is not one file: each chip is a core, each core is testable, and the window manager owns the frame the way it owns every other application.

08 — Console / native target

イリス (Iris PS2) 実機稼働

Iris はエミュレータではありません。B-System が PlayStation 2 の実機そのものに起動します。 GS（グラフィックスシンセサイザー）へ GIF を組む道、VU0 と VU1 の幾何パイプライン、パッドと USB、IOP の RAM と割り込みまでが src/drivers/ps2/ にあり、make ps2 は一枚の ISO に落ちます。

  • 起動boot_ps2.s と ps2.ld
  • 描画ps2_gs.c、ps2_gif_ring.c、ps2_gs_tex.c
  • 幾何VU0 / VU1 — マイクロコード付き
  • 実測scripts/ps2_bench.sh がゲスト内部の時間と実行側の時間を分けて採る

Iris is the console as host, not as guest. The same C99 sources link against PS2 silicon, and the benchmark separates the clock inside the machine from the clock outside it.

09 — Machine / announced

メガドライブ (Genesis) 準備中

席だけの宣言です。src/emulators/sega/ はツリーにありますが、中には空の目印だけが置いてあります。68000 のコアも、VDP の再現も、まだ書かれていません。

  • あるもの：ディレクトリと名前
  • ないもの：コア、画面、スクリーンショット

Genesis is a reserved seat. No core, no frame, no screenshot.

10 — Machine / announced

アミーガ (Amiga) 準備中

同じく席だけです。src/emulators/amiga/ は空の目印を持つプレースホルダです。なお 68000 系の CPU そのものはカーネルの側に存在します。src/cores/core_m68k.c は Motorola 68040 上の BTRON カーネルで、アミーガのエミュレーションではありません。

  • あるもの：ディレクトリと名前
  • 別の場所にある似たもの：68040 のカーネルポート
  • ないもの：アミーガとしての実装

Amiga is a reserved seat. The 68040 kernel port elsewhere in the tree runs B-System on that CPU family; it is not an Amiga.

11 — Machine / plan only

アレス (Ares N64) 準備中

計画段階の名前です。ツリーには何もありません。B-GL のロードマップが四つのハードウェアバックエンドを掲げるなかで、N64 はその訪問先として名前を残しています。

  • あるもの：この名前だけ
  • 関連する宣言：B-GL の HW バックエンド四つ
  • ないもの：RDRAM、RSP、RDP、カートリッジ、画面

Ares is a name on a roadmap. Nothing in the tree backs it yet, and the card keeps that visible instead of implying a feature.

03 / Substrate

第三部：同じ床

Four constants · one audio path · one window contract

十一の札は、四つの数と、一本の音の道と、一つの窓の約束でできています。創作アプリもゲームも、同じ平面予算の中で動き、同じ交互 PCM を同じデバイスに書き、同じ実身／仮身の文書モデルを読みます。だから「四つのアプリと七つの席」は別々の製品の寄せ集めではなく、同じ約束の十一の使い方です。

The eleven tiles are made of four constants, one audio path and one window contract. Authoring and playing share the per-plane CPU and buffer budgets, the same interleaved PCM written to the same device, and the same real-body / virtual-body document model. That is why the two families are one operating system rather than a bundle — and every number on this page is readable in the sources it comes from.

一枚のデスクから始める

どの札も、デスクの上の窓です。まずワークベンチを開き、次に使うものをひとつ選んでください。オーケストラで一曲取り、電子帳票で一頁組み、ゲームシステムでカートリッジを一本回す。そのどれにも、このページがリンクした先に、窓口と操作と内部構造の順番をもった仕様書があります。

Every tile is a window on one desk. Open the Workbench, choose one thing, and the specification behind that tile is ordered the same way: what the window is, how it is operated, and how it is built.
